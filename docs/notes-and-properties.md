# Notes and properties

## Note page
- `Editor` switches between `MarkdownPreview` (read-only apart from task checkboxes, accordions, links' menus and dragging list items and blocks; open accordions stay open across re-renders) and `MarkdownEditor` (highlighted textarea; the line the cursor is on, every row it wraps to, has a highlighter band behind it (`bg-marker`, a light but bright yellow-green, like a marker; it glides to a new line in 150ms and never blinks, the cursor taken with the text on every change), so where a double tap put the cursor, and where it is now, shows; Enter in a list continues it with the next `-`, number or `- [ ]`, and on an empty item ends it: `continueList`; typing `[[` opens a popover at the caret listing the repo's notes and files (not hidden ones or the note itself), narrowed by what's typed after it, names first (`typedLink`, `linkTargets` in `lib/links.js`); styled as a menu (its corners, padding and keyboard highlight); ↑ ↓ and Enter (once something's typed or chosen; right after `[[` Enter is a new line; with a modifier the keys do what they always do) / Tab or a tap put in the link to it from the root, as Copy link makes it (`repoLink`), Escape closes only the list).
- ✏️ opens the editor at the first block on screen (`visibleOffset`); a double tap or double click on text opens it at that word (on empty space under or between the text: at the end of the note) (counted from two clicks, since iPhones send no dblclick). Closing the keyboard (iOS Done, tapping elsewhere, Esc) or ✓ returns to preview. The finishing ✓ follows the ✓ button rules.
- **Undo and redo while editing:** the title bar's ⋯ gives way to Undo and Redo (`ArrowUUpLeft` / `ArrowUUpRight`, lightly filled like ←, `ghost-outline`; disabled when there's nothing to undo or redo), and Ctrl/⌘+Z, Shift+Ctrl/⌘+Z and Ctrl+Y do the same (`useUndo`, `lib/undo.js`, tested; the browser's own undo would lose track of text the app sets). Typing in one burst (each change within a second of the last) is one step, up to 200; the cursor goes to the end of what changed; a tap on them keeps the keyboard and the editor open. A change from outside the editor (the note loading, a sync bringing in GitHub's text) starts the history afresh, so undo never takes back what wasn't typed here. The history lasts while the note is open.
- **Links in the preview** are badges (`LinkBadge`, put in place of each `<a>` by `linkSpots`), even mid-sentence: a website's favicon (Google's favicon service; a globe offline or without one), or for the repo what it points to (its emoji when it has one, else note, file, folder; grey link-break when missing), then the link's text, a bit softer than the note's (`text-foreground/75`); at most 420px wide or its container's width, a longer text cut in the middle so its end shows (`MiddleCut`); a tap opens it. Its ⋯ (small, 24px, to fit the line), split off by a 1px gap: Copy link (`CopyLinkItem`, as in every ⋯: a repo link as a markdown link to its target, `repoLink`; a website's address, or the link as written when its target is missing), Edit link (`LinkModal`: Name and URL; a bare URL stays bare while it has no other name) and Remove (the link and its text, confirmed). Edits go through `onChange` like a checkbox, found by `linkSpans` (lib/markdown.js, tested), and refused with a toast when the note changed there since the dialog opened; a block whose links don't line up with them (raw HTML links) only offers Copy. Links to a heading (#…) and around an image stay plain. A property's description (note page, board cards) shows its links as the same badges, with the same menu (`InlineMarkdown`; Edit link and Remove change the description). Both use `useLinkEdits`.
- **Dates in the text** (`lib/dates.js`) are written in one form, "17 Oct 2026, 14:30" ("17 Oct 2026" without a time). Every date badge (the preview, properties, planner cards and rows, a repeat's end) shows it without the year when it's this year ("17 Oct, 14:30", `dateLabel`); another year's keeps it. The note's text always keeps the year. Recognized: 2026-10-17, 17.10.2026, 17/10/2026 (day first), 17 Oct, 17th of October 2026, Oct 17, 2026, each optionally with a time on the same line (14:30, 2:30pm, 2pm, at 14:30, T14:30). A time on its own (14:30, 9:05, 2:30pm, 2pm, 9 a.m.; minutes have 2 digits, so 3:1 isn't one) is written "14:30". Without am/pm a one-digit hour from 1 to 6 is the afternoon ("2:30" is 14:30; "02:30" and "9:05" are as written). A year has 4 digits (17.10.26 isn't a date); a missing one is the current one. A month starts with a capital letter ("march" is a word), except right after its day ("5 oct"); words like "tomorrow" aren't dates; nothing reaches across a line break or into a file name (2026-10-17.md). Only where the preview shows plain text: never in code (fenced or indented), links or HTML (`withFixedDates`, `textRanges` in lib/markdown.js).
- **Every date in the note is rewritten when the editor closes** (✓ or Done, or leaving the page or view while still editing; even with nothing typed): `useNote`'s `beginEdit` / `endEdit`. Closing the browser tab while editing saves the typing as it is. If formatting fails, the note is saved as typed, with a message. **Properties too:** each value gets its dates written the same way, as text; a list item that gets a comma (a time) moves its list onto `- item` lines (`withValue`), so it stays one value.
- **The preview** shows every date, in any form, as a badge in the line (`DateBadge`, in place of each date spot `<time>`, which keeps what's typed in `data-raw` for list dragging and a double tap): a calendar, then the date, no ⋯; grey, icon too, and small (20px, text-xs) so the line keeps its height. Tapping it opens the one date picker (`DateField`, `DatePopover`, shadcn's `Calendar`), the same whatever is written (a day, a time alone with a clock icon, both): the Calendar, Remove date (red trash) when there's a day, then + Add time when there's no time, else the time field with a red trash (Remove time). A picked day replaces the day, its time kept; a time (saved on Enter or leaving the field) is set or added; taking out the day keeps the time and the reverse. A date in the text can't be emptied: its last part has no Remove (`required`) (`useDateEdits`: the i-th spot is the i-th date of `dateSpans`, and only when it's still what's typed there). A description's dates (note page, board cards) work the same.
- **A date property** (its value one date, or while empty every value the notes nearby have one: `isDateProp`, `valueDate`) shows the same grey badge at the size of the other property badges, calendar icon on the left and no ▾, and opens the same date picker instead of the values list; taking out its last part (or the same day tapped again, without a time) empties it. The planner's Go to a day and a repeat's end date use it `dayOnly`: no time, never emptied.
- **Dragging list items** (bullets, tasks, numbers) in the preview: a ⠿ handle (`ListGrip`), shown like a block's (a mouse: only while the item is hovered; touch: faint), in the note's left gutter, the same column as a block's, so a list sits on the text's own level (App.css) (hold 0.25s on touch to drag, as on the board). An item moves with its sub-items and can be dropped next to any item of the note, in another list too (`@dnd-kit`; a line marks the item it lands before or after: above the middle of it before, below after); it takes the marker and indent of the list it lands in, and the ordered lists it left and joined are numbered again from their first number. Pure logic in lib/markdown.js (tested): `listsIn` finds the items in a list block's markdown (handles only where they match the rendered items in number and first word), `moveListItem` writes the move, through `onChange` like a checkbox. A block whose lists don't line up with the markdown (a list in a quote) has no handles.
- **Markdown inside HTML** reads as everywhere else (lib/markdown.js, tested): in an HTML block the text between tags is markdown, its tags stay HTML. Text starting on a line of its own reads as blocks (a list right under `</summary>`, no blank line needed); text right after a tag as one line, a heading when it starts with `#` (`<summary>### Title</summary>` titles an accordion with an h3), else inline (bold, links and dates, as badges). Code, `<pre>`, scripts, styles and comments stay as written. An accordion's title is one piece beside its caret (`.summary-title`); the caret and the block's grip sit on the title's first line, in a heading title's size.
- **Dragging blocks** (a paragraph, heading, list, quote, code block, table, accordion…) in the preview: a ⠿ handle (`ListGrip` in a `.block-grip` spot, `blockGrips`) in a left gutter as wide as a grip (the note indents by it; App.css), at the block's first line (none on a list whose items have their own: they are what's dragged); with a mouse shown only while the block is hovered, on touch always, faint. A block moves among the note's blocks, a line marking the one it lands before or after, as for list items (as in Notion: the dragged one stays in place, faded, a half see-through copy follows the pointer or finger up and down, `DragOverlay`, and the line, 2px in the accent like the resize handle's, sits in the gap above or under the one it's over, drawn over that copy; dragging a handle never pulls to refresh) (`@dnd-kit`, the same sensors). `moveBlock` (lib/markdown.js, tested) writes the new order through `onChange`: a heading takes its section along (`blockSection`: everything under it down to the next heading of its level or higher; dropped inside itself, nothing changes); what lies between blocks (blank lines, link definitions) stays in place, with at least a blank line next to a moved block so it never runs into its neighbour, while blocks that were already together keep their own line breaks; two lists that end up next to each other are joined by a line break into one tight list (a blank line would merge them into a loose one); the front matter stays on top. A loose list (a blank line between items) is spaced like a tight one, with a gap only where blank lines are written, as tall as how many (`gap-after` and `--gap-lines` on that item, lib/markdown.js: one is a paragraph's gap, each more adds a line; App.css).
- The preview never scrolls sideways: text wraps; a wide table or code block scrolls inside itself (a table column is at least 10rem wide, `min-width` in `App.css`). A note's `# heading` is plain markdown.
- **Table columns:** every table with a header and rows has a type per column (`lib/tables.js`, tested): Text, Number, Select, Multi-select, Date, Checkbox or Link. Without a picked type a column gets the one its cells look like (`detectType`: ticks such as x / ✓ / yes / no → Checkbox; numbers such as 1,200 / 3,5 / 12% / $40 → Number; dates → Date; cells that are only links → Link; short values repeating across rows → Select, or Multi-select when written with commas; else Text). A type picked for a column is how Folio shows it, kept per note and column name in `.folio/tables.json` (`useTables`, `TablesContext` in App), with the colors picked for its values; it follows the note when it moves and goes when it's deleted; deleting `.folio` brings back the detected types. The cells' text stays the content: a Select cell shows its value as a badge, a Multi-select cell one badge per comma-separated value, a Date cell a date badge, each opening the same popovers as a note's properties (`TableCell` → `PropertyBadges`: choose or add a value, Edit values to rename, recolor or remove one in every row of the table, a calendar); a Checkbox cell is a checkbox (ticking writes the column's own words: yes / no, true / false, [x] / [ ], else x and nothing, `checkboxText`); Number cells are aligned right; Text and Link cells show as written. A typed cell's own content stays in the page, hidden, so the note's date badges and images keep lining up with its text. A change rewrites the cell in the note's table (`withCells`; a `|` is escaped, and one in `code` splits cells as on GitHub, a short row gets the cells it lacks; only in a table that is a block of its own, not in a quote or a list, `tableRows`); a locked note's cells only show. After each header's text, a small button (`TableColumn`: the type's icon; accent-colored, a sort arrow or a filled funnel while it sorts or filters) opens Type (a sub popover: Automatic, naming the detected type, then every type), Sort (None and the type's two directions: A–Z, 1–9, Oldest / Newest, Open / Done first; empty cells last; one column at a time, `sortedRows`) and the type's filter (`cellPasses`): a Select's or Multi-select's values to tick, with how many rows have each; a Number's Min and Max; a Date's From and To (days); a Checkbox's All / Not done / Done; Text and Link only sort. Clear filter shows every row again; filters in several columns all apply, and a table they leave empty says "No rows match the filters." Sorting and filters are never saved: they last while the note is open. Cells are centred vertically. **Rows drag** by a ⠿ handle at the start of their first cell (`.row-grip`, `ListGrip` with the row as its item; with a mouse shown while the row is hovered, on touch always, faint), only among that table's body rows, never above the header, a line along the edge of the row it lands next to; `moveTableRow` (lib/tables.js, tested) writes the new order. Only where the table's rows line up with its markdown (`edit`), and not while it's shown sorted.
- **Image width** is written after the alt text, as Obsidian does: `![photo|300](a.png)` (`|300x200` reads as 300; other viewers show it only as alt text). With no width an image is as big as it comes, at most the width of the note. In the preview an image shows a grip on its right edge (`ImageHandle`; hover, always on touch; arrow keys too): dragging resizes it live, between 48px and the note's width, and on release writes the width into the note (`withImageWidth`, `imageSpans`, `splitImageAlt` in `lib/markdown.js`). Not offered for images inside a link, in a read-only preview, or when the note has raw HTML `<img>`s (the preview can't tell which markdown image is which).
- Images and PDFs open read-only in `FileViewer` (`useBlob`); PDFs use pdf.js (`PdfView`, loaded on first use) and draw only pages near the screen, for iOS memory. `Editor` and `FileViewer` share `FilePage`.

## Properties (front matter)
- Shown on top of the preview in a light grey box (`bg-secondary/50`, 16px padding, 16px under its title) titled Properties (`PropertyBadges` with `title`; a double tap opens the editor at the start of the file; board cards use it bare), in the file's order.
- The `description` (`DESCRIPTION`) is muted text whose markdown links are link badges, opened like the note's own, and whose dates are date badges (`renderInline`); never a badge. Every other value is a badge (no property name, no tooltip). Badges listed before the description show above it, the rest below.
- Each badge has a ▾ and opens a popover to change that property, through `useNote`'s `change` in a note and `setProperty` on a board card (both `withValue`).
- A click, press or touch inside a badge or its popover doesn't reach the note or card (`own`). The editor shows the raw block.
- **A widget's properties** (`valueScope`, e.g. a planner's `date` and `repeat`): on the note's page its `order` comes first (a planner's: description, date, repeat); in the editor their lines (`keyLines`: the key's line and its `- item` lines, in a closed front matter block) are greyed out and typing that would change, add or remove them is refused with a message (`MarkdownEditor` `locked`); and when the text was changed in the editor and lacks one (`required`, also a board's group property), it comes back, empty, as the editor closes (`useNote`), moved into that `order` in the file (`withKeysFirst`).

## Value popover (`ValueChooser`)
- A field to find or add a value (shown from 10 values, or with none; in between, **Edit values** adds), the values the notes next to it have for that key (the note's folder; on a card, and on the page of a note that is a card of any board, the whole board: `valuesOf`, `valueScope`) with a ✓ on the current ones, on a board's card, the board's hidden columns of its group property are listed too, marked with an eye-slash (`hidden` of `valueScope`); then a separator and **Edit values**.
- A property with a list toggles values and stays open; a single-value property takes the chosen one (choosing it again empties it) and closes. An empty property shows its name as a badge to fill. Without `onChange` (a card being dragged) badges are plain and empty ones aren't shown.
- An outside click or Esc closes it.

## Values dialog (`ValuesModal`, from Edit values)
- One dialog with every value of the property, a field to add one (it's set on this note, like choosing it; on a single-value property a line under the field says which value it replaces), and on each row a color swatch, a pencil and a red trash.
- **Swatch:** a sub popover on its side with the ten colors (`ColorPicker`); choosing one recolors that value at once, without touching any note.
- **Pencil:** the row becomes a name field with only ✓ / ✕ until you accept or dismiss. Save renames the value, keeping its color, in every note in scope. A name another value has merges them (the row says so), in that value's color. Old names keep their picked colors: colors are repo-wide, and the old name may still be used elsewhere.
- **Trash:** closes the dialog, asks first (`ConfirmModal`, with the number of notes), then empties that value in scope.
- **Scope:** the note's folder, or the whole board for a board's card (on the card and on its page). The same actions for both (`valueActions` in `lib/frontmatter.js`): this note changes through `change`, the others through `editNote` (`renameValue`, unchanged when the name is; `withoutValue`: empty for a single value, out of the list for a list).

## Colors
- Each value has its own badge color within its property, `--tag-0`…`--tag-9` tinted by `--tag-tint` against `--card`, stronger on hover; an empty one is grey.
- Automatic (`valueColors`): a value prefers the color its name hashes to, a taken one gets the next free; up to ten values differ.
- Picked colors are saved by key and value for the whole repo (not per folder) in `.folio/colors.json` (`useTagColors`, `lib/tagColors.js`). A picked color wins over the automatic one, and other values avoid it. An unreadable file is never saved over.
