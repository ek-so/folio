# Files, links and sync

## Item actions
Rename / Move / Remove for any file or folder (the only way to rename) go through `ItemMenu` (⋯) on list rows, tree rows and the title bar. A file's ⋯ also has Duplicate: a copy next to it ("x 2.md", `freePath`), a note's text with " (copy)" after its title (`copyTitled`), else (a file, or a note not on this device) the same bytes (`duplicate` in lib/changes.js; a blob GitHub already has isn't uploaded again on push); a symlink can't be duplicated. Every ⋯ of a file or folder (and a board card's) has Copy link: a markdown link to it from the repo's root (`[Name](/path/to/Name.md)`, `repoLink`) to paste in another note; it follows renames like any link. `SearchSheet` finds visible files by path, and the app's Search folders too (listed first); with no query it lists recently opened files. The app's Search always opens what you pick in File manager.

## Automatic sync
Folio syncs once by itself when it opens or reloads (or, if it opened offline, when it's back online): the same Sync as the button, with no "Synced" toast when it works. Conflicts and failures show as they do for Sync (conflicts, the error sheet); offline says nothing (the button does); broken links stop it with a "Not synced" message and Review, not a sheet opening on its own.

## Emoji icons
Emoji in a file's or folder's ⋯ (`ItemMenu`: a sub menu with `EmojiGrid`: a search field (by words; an emoji pasted into it is picked), the grid and a red ✕ that removes it) replaces its type icon everywhere (`FileIcon`: tree, list, cards, search, title bar, a view's notes). Kept in `.folio/icons.json` (`lib/icons.js`, `useIcons`): how Folio shows the file, so deleting `.folio` only brings the type icons back; it follows moves and the archive, and a file deleted for good drops it. An emoji a name (or a note's title or heading) starts with is the icon until one is chosen, and every name is shown without it (`displayName`, `withoutEmoji`); the file isn't renamed, and links keep its own name (`fileName`).

## Symlinks
- Git mode `120000`. A link never opens itself: opening one (from the list, search or a note's link) opens its source. A link row is dimmed with "(symlink)" after its name (tooltip "Symlinked from <path>"). Links outside the repo, to nothing, or not on the device yet show the reason and can't be opened. Folder links sort with the folders.
- A file or folder that links point to shows them in its title bar after the title (`SymlinkedBy`): a grey ↘ badge that shows the link's name and opens it, or (↘ and a count) lists their paths.

## Links
- `useLinkIndex` indexes every note (local edit, else the offline copy) on the device; nothing is stored in the repo. Notes show `Backlinks` under the preview.
- Sync and Push first check the whole repo for broken links; if any, `SyncCheckModal` lists them (`BrokenLinkList`, shared with the Broken links page) with Fix, Open Broken links and Sync anyway.
- Rename and Move rewrite every affected link in the same local changes; the sheets say how many notes are affected (`LinksContext`).

## Locked files
Lock in a note's ⋯ (its page) or a card's ⋯ (board, planner, the planner's list) locks it against editing; Unlock (the same menus, or the lock icon in place of ✏️ on its page) frees it. Kept in `.folio/locks.json` (`lib/locks.js`, `useLocks`): how Folio treats the file, not what it says, so deleting `.folio` only unlocks. A locked note: no ✏️ or double tap, no ticks or list dragging, no badge values, links or dates changed; a locked card: a small lock before its title, no Edit title / description, no values, no dragging to another column or day, no Move to column, Mark as done or Remove. Removing it from anywhere (or a folder holding one) is refused with a message. Rename, Move and Duplicate stay (the copy starts unlocked); the lock follows its file (`moved`, the archive too) and a file deleted for good drops it. Every widget edit, and a note's values changed across its folder, goes through `guarded` (App): whatever it changed in a locked note's text is put back (`keptEdits`, lib/changes.js); the app's own link rewrites after a rename or move still reach it, so its links keep working.

## Uploads
Drop files on the file list (into the open folder or onto a folder row) or + → Upload files…. `handleUpload` stores each file's bytes in the offline cache under its git sha and records an upload in the local changes; Sync uploads the blobs in the one commit. A taken name asks Replace / Keep both / Skip (`UploadClashModal`); the file is placed against the changes as they are once it's stored (a free name is picked then); invalid or over-25 MB files are listed in `UploadErrorsModal`. Unused bytes are dropped from the cache.

## Offline and sync
- A service worker (vite-plugin-pwa) caches the app, and all notes are prefetched to IndexedDB.
- **Archive:** Remove (a file, note or folder, from any ⋯; a board column's cards) doesn't delete: it moves it into `.archive/<day>/` at the root, today's folder (a taken name gets a number), in one step with its links rewritten; a page showing it closes and widgets find it gone (`relocated` without `follow`), and a toast offers Undo (several files at once get one toast, without), which puts it back in its own place, or next to it when that's taken since (`freeTarget`, `renameError`: the place it moved away from is free for it). The confirmation says it can be recovered there for 30 days. A planner's Mark as done archives a card the same way, with `status: done`. Something already in the archive is removed for good. When Folio opens, the day folders older than 30 days are removed as local changes, with a message, so they go on the next Sync and can still be discarded (`lib/archive.js`).
- Every change is local until Sync, which makes one commit. The local changes are stored in localStorage on every change; when that fails (storage full), a message stays until they're stored again. An open note shows its text as the local changes have it, so a change made elsewhere (a link rewritten by a rename, a widget's edit) isn't overwritten by the next typing; typing not reported yet wins.
- Sync, Push and Pull run one at a time (`run`; one asked for meanwhile, a double tap, is ignored), each after the open note's typing is saved. GitHub's state after it is computed locally (`filesAfter`, `blobSha`), so a dropped connection can't leave pushed changes looking unsynced.
- The app never downloads GitHub's changes by itself: on start, return, coming online and pull-to-refresh it only checks for new commits (`checkRemote`) and shows the dot. Files change only on Sync or Pull (a repo never opened on this device downloads on start).
- **`SyncButton`** is one button everywhere (a plain `ghost` item in the rail; on the phone bar an icon button) that opens the sync menu: Sync all (blue badge: the total to push and pull; "7+" or New when GitHub can't count), then Push / Pull (badges; "New" when GitHub can't compare) / Discard (confirmed). The rail item's badge shows only directions (↑ ↓); icon-only ones a dot. It flashes only Failed and Offline.
- Success shows a toast (Synced / Pulled; `useRepo` reports it through `onDone`). A failed Sync / Push / Pull (not offline) opens `SyncErrorModal` (`describeSyncError`: what happened, what to do, GitHub's raw answer, the failed step, Try again).
- `lib/updates.js` reloads for new versions on start and on return, never while typing.
