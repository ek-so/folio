# Files, links and sync

## Item actions
Every file's and folder's ⋯ is one `ItemMenu`, wherever it shows (list rows, tree rows, the title bar, Assets, a board's or planner's card, a pinned note or folder; what it does is App's, given once through `ItemActionsContext`). Its sections, in this order: what only that place offers (a card's Mark as done, Edit description and Move to column; Show in folder, which opens its folder in File manager, on Assets, cards and pinned items), then the core, the same everywhere: Rename (the only way to rename) · Emoji · Move to… · Duplicate (files) · Copy link · Open on GitHub (where GitHub has it, before a rename here; none until it's pushed) · Lock / Unlock (files), then Remove (a pinned item's: Remove from widget, which keeps the file). Duplicate: a copy next to it ("x 2.md", `freePath`), a note's text with " (copy)" after its title (`copyTitled`), else (a file, or a note not on this device) the same bytes (`duplicate` in lib/changes.js; a blob GitHub already has isn't uploaded again on push); a symlink can't be duplicated. Copy link: a markdown link to it from the repo's root (`[Name](/path/to/Name.md)`, `repoLink`) to paste in another note; it follows renames like any link. `SearchSheet` finds visible files by path, and the app's Search folders too (listed first); with no query it lists recently opened files (the last 15 in the open repo, kept on the device across sessions; cleared on sign out). The app's Search always opens what you pick in File manager.

The square behind a card's icon in File manager's Cards takes the emoji's own color (`lib/emojiColor.js`: its pixels averaged, once per emoji, a light mix of it that darkens on hover; `iconTint`).

## Moving emojis from names to icons
Settings → Emoji in names → Move to icons (after a confirmation sheet; `moveEmojisToIcons` in App, `emojiNamed` in `lib/icons.js`) takes the emoji off every file and folder name that starts with one and makes it that item's icon, in one step: shallowest first (a folder's files follow it), a taken name gets a number ("Plan 2.md"), links are rewritten like any rename, an icon already chosen is kept, and `.folio`, `.archive` and hidden names are left alone. Notes' `title` properties and headings are never touched. Nothing is pushed until Sync.

## Assets
Assets (rail, ☰; a fixed page like Settings, `components/Assets.jsx`) lists every file that isn't a note, with its path as the row's description, newest added first (`assetList` in `lib/assets.js`; `.folio`, `.archive` and `.gitkeep` left out); a row opens the file in File manager (← goes a level up as usual; a file Folio can't show, neither an image nor a PDF nor a note, doesn't open, like in File manager). On the right, a ↗ button (`ArrowSquareOut`, medium) opens the note that links to it (the link index's backlinks): one opens at once, several list in a menu, none shows no button; then its ⋯ (`ItemMenu`: Show in folder, Rename, Move, Duplicate, Copy link, Emoji, Remove) acts on the file. In the title bar a filter button (`TypeFilter`, a Funnel) lists the file types by extension with their counts (`assetTypes`; All types first, then most files first); choosing one narrows the list (`filterAssets`, the count line says "3 of 12 files"), lit while one is chosen; it's kept while the page is open, and hidden when there's only one type. Full width of the page's 1000px column. When a file was added is noted when it's uploaded here, in `.folio/assets.json` (`useAssets`): it only orders the list, follows moves, the archive and deletes (`lib/pathMap.js`, shared with the emoji icons), and a file added elsewhere sorts after the rest by path. No sizes: git's tree isn't read for them.

## Search
`SearchSheet` (rail, ☰): a query finds folders, then files, by path, then notes by what they say (`lib/search.js` `searchNotes`: any case, from two letters, up to 20; each under its name with a snippet of its text, the match highlighted). It reads the texts the link index already holds (`notes`: local edits, else the offline copy), so only notes on this device are searched; PDFs and images are found by name only. Other pickers (Notes' Add note…) search names only.

## Automatic sync
Folio syncs by itself, so the Sync button is only a backup (`useAutoSync`, App): a full Sync when it opens or reloads (or, if it opened offline, when it's back online); while it's on screen and online, a check for new commits on GitHub every minute (`PULL_EVERY_MS`) and when it comes back to the screen or online (`checkRemote`: one conditional request, which GitHub doesn't count against its limit when nothing changed), pulled and merged when there are some; and a Sync 30 seconds after the last local change (`PUSH_AFTER_MS`; each change starts the wait again), at once when the app goes off screen. Nothing runs while another step does or the app is hidden. All of it is quiet: no "Synced" toast when it works; failures show as they do for Sync (the error sheet), then it pauses for 5 minutes (the button still syncs at once); offline says nothing (the button does); broken links stop pushing with a "Not synced" message and Review (once per count), not a sheet opening on its own.

## Emoji icons
Emoji in a file's or folder's ⋯ (`ItemMenu`: a sub menu with `EmojiGrid`: a search field (by words: an emoji's name, and for Suggested ones extra words like "home"; an emoji pasted into it is picked), a scrolling box of every emoji this device can draw in groups under small titles (Suggested first, then Unicode's groups, `lib/emojis.js` `emojiGroups`; the list, `unicode-emoji-json`, is loaded once on demand and the newest emoji version the device draws found on a canvas, `hooks/useEmojis.js`; Suggested alone until it loads), and a button back to the default icon) replaces its type icon everywhere (`FileIcon`: tree, list, cards, search, title bar, a view's notes). Kept in `.folio/icons.json` (`lib/icons.js`, `useIcons`): how Folio shows the file, so deleting `.folio` only brings the type icons back; it follows moves and the archive, and a file deleted for good drops it. An emoji a file's or folder's name starts with is its icon until one is chosen, and the tree, lists, search and title bar show the name without it (`displayName`, `withoutEmoji`; the file isn't renamed, and links keep its own name, `fileName`). For a note's `title` or heading, the text stays as written, emoji included: Rename never drops one.

## Symlinks
- Git mode `120000`. A link never opens itself: opening one (from the list, search or a note's link) opens its source. A link row is dimmed with "(symlink)" after its name (tooltip "Symlinked from <path>"). Links outside the repo, to nothing, or not on the device yet show the reason and can't be opened. Folder links sort with the folders.
- A file or folder that links point to shows them in its title bar, inside the name button after ▾ (`SymlinkedBy`): a grey ↘ badge that shows the link's name and opens it, or (↘ and a count) lists their paths.

## Links
- `useLinkIndex` indexes every note (local edit, else the offline copy) on the device; nothing is stored in the repo. Notes show `Backlinks` under the preview.
- Sync and Push first check the whole repo for broken links; if any, `SyncCheckModal` lists them (`BrokenLinkList`, shared with the Broken links page) with Fix, Open Broken links and Sync anyway.
- **A new note** always asks for a **Title** and a **File name** (`NewFileModal`, `TitleNameFields`, `useTitleName`); both are required. The file name follows the title in kebab-case ("Use Lidl coupon" → `use-lidl-coupon`, `nameFromTitle`) until it's typed in (an emptied name shows the kebab-case as its placeholder and Save uses it); the title becomes the note's first heading. A folder only has a name. **Rename** of a note on this device (`RenameModal`; ⋯ anywhere, a card's ⋯, a Pinned widget's card's ⋯) is the same two fields at once: the title is written where the note's title comes from (`withNoteTitle`: its `title` property, else its first heading, else a new `title` property) in the same change as the rename; the name follows the title only while it still matched the old title's kebab-case. A note not on this device, a locked one, any other file, a folder, a view or a column has the one name field.
- Rename and Move rewrite every affected link in the same local changes; the sheets say how many notes are affected (`LinksContext`).

## Locked files
Lock in a file's ⋯ (anywhere: its page, a row, a card, a pinned card) locks it against editing; Unlock (the same menus, or the lock icon in place of ✏️ on its page) frees it. Kept in `.folio/locks.json` (`lib/locks.js`, `useLocks`): how Folio treats the file, not what it says, so deleting `.folio` only unlocks. A locked note: no ✏️ or double tap, no ticks or list dragging, no badge values, links or dates changed; a locked card: a small lock before its title, no Edit description, no values, no dragging to another column or day, no Move to column, Mark as done or Remove. Removing it from anywhere (or a folder holding one) is refused with a message. Rename, Move and Duplicate stay (the copy starts unlocked); the lock follows its file (`moved`, the archive too) and a file deleted for good drops it. Every widget edit, and a note's values changed across its folder, goes through `guarded` (App): whatever it changed in a locked note's text is put back (`keptEdits`, lib/changes.js); the app's own link rewrites after a rename or move still reach it, so its links keep working.

## Uploads
Drop files on the file list (into the open folder or onto a folder row) or + → Upload files…. `handleUpload` stores each file's bytes in the offline cache under its git sha and records an upload in the local changes; Sync uploads the blobs in the one commit. A taken name asks Replace / Keep both / Skip (`UploadClashModal`); the file is placed against the changes as they are once it's stored (a free name is picked then); invalid or over-25 MB files are listed in `UploadErrorsModal`. Unused bytes are dropped from the cache.

## Offline and sync
- A service worker (`src/sw.js`, vite-plugin-pwa) caches the app, and all notes are prefetched to IndexedDB. The page itself comes from the network first, so online Folio always opens in its newest version; offline, or when the network doesn't answer within 3s, the cached page opens.
- **Archive:** Remove (a file, note or folder, from any ⋯; a board column's cards) doesn't delete: it moves it into `.archive/<day>/` at the root, today's folder (a taken name gets a number), in one step with its links rewritten; a page showing it closes and widgets find it gone (`relocated` without `follow`), and a toast offers Undo (several files at once get one toast, without), which puts it back in its own place, or next to it when that's taken since (`freeTarget`, `renameError`: the place it moved away from is free for it). The confirmation says it can be recovered there for 30 days. A planner's Mark as done archives a card the same way, with `status: done`. Something already in the archive is removed for good. When Folio opens, the day folders older than 30 days are removed as local changes, with a message, so they go on the next Sync and can still be discarded (`lib/archive.js`).
- Every change is local until Sync, which makes one commit. The local changes are stored in localStorage on every change; when that fails (storage full), a message stays until they're stored again. An open note shows its text as the local changes have it, so a change made elsewhere (a link rewritten by a rename, a widget's edit) isn't overwritten by the next typing; typing not reported yet wins.
- **Changed on both sides** (a file touched here whose GitHub version changed since, `conflicts`): Sync and Pull merge it into the local changes before going on, so nothing is overwritten or thrown away (`mergeConflicts` in `useRepo`, `resolveConflicts` and `mergeText` in `lib/merge.js`, tested). Text is merged line by line against the version this device last had: a part changed on one side takes that change, a part changed on both keeps both, this device's lines first (a removed line the other side changed stays). A note's properties are merged one by one: one changed on both keeps this device's value, and GitHub's line goes into the note right under the front matter. Removed on one side and changed on the other: the changed one stays (made anew if GitHub removed it). Moved here, changed on GitHub: GitHub's content at the new place. Another file (image, PDF) changed on both: GitHub's keeps its name and this device's is added beside it as "name (this device).ext". A toast names the merged files.
- **Another device pushing in between** (GitHub refuses to move the branch back, 409/422 on the save, `isOutOfDate`): Sync pulls, merges and pushes again by itself, up to 3 tries in all (`SYNC_TRIES`), before the error sheet. **A very large repo** whose listing GitHub cut short (`truncated`): every file this device touched that the listing left out is asked for on its own (`complete`, `fileOn`), so it isn't taken for removed.
- Sync, Push and Pull run one at a time (`run`; one asked for meanwhile, a double tap, is ignored), each after the open note's typing is saved. GitHub's state after it is computed locally (`filesAfter`, `blobSha`), so a dropped connection can't leave pushed changes looking unsynced.
- A repo opens with GitHub's latest: one never opened on this device downloads on start, and a stored one with nothing unsynced is pulled first, Folio showing loading up to 15s (`PULL_WAIT_MS`) before showing the stored copy, which the latest replaces when it comes, typing in an open note saved first, if that left nothing unsynced and no sync is running (offline: the stored copy). Then Folio syncs by itself as described above (`useAutoSync`). Coming back to the screen with new commits on GitHub, the page shows loading while they're pulled (`catchingUp`, up to `PULL_WAIT_MS`), typing saved first; the page stays mounted underneath, hidden, so an open dialog keeps what's typed in it, so what was there before never shows as current.
- **`SyncButton`** is one button everywhere (a plain `ghost` item in the rail; on the phone bar an icon button) shows the sync's state (Synced with nothing waiting, Sync with something to push or pull, Syncing… while a step runs) and opens the sync menu: Sync now (accent badge: the total to push and pull; "7+" or New when GitHub can't count), then Push / Pull (badges; "New" when GitHub can't compare) / Discard (confirmed). The rail item's badge shows only directions (↑ ↓); icon-only ones a dot. It flashes only Failed and Offline.
- Success shows a toast (Synced / Pulled; `useRepo` reports it through `onDone`). A failed Sync / Push / Pull (not offline) opens `SyncErrorModal` (`describeSyncError`: what happened, what to do, GitHub's raw answer, the failed step, Try again).
- `lib/updates.js` checks for new versions on start and on return. A new version takes over as soon as it's ready; the page reloads only when it's older than that version (an app left open; one that came from the network already is it), never while typing.
