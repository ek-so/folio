# Views and boards

## Views
- A view is a dashboard (`ViewPage`): a title bar with ⋯ and + → Add widget (every kind in `widgets/index.js`) over its widgets stacked full width, then an Add widget button under them. Empty: an Add button per kind.
- The view's ⋯: Edit widgets (`EditListModal`: drag rows into order, saved on each drop by `moveWidget`; a row's trash removes that widget, confirmed on top of the sheet), Rename, Remove. The navigation's ⋯ keeps only Rename and Remove. A kind this version doesn't know is kept, shown as such, and can be removed. Saved in `.folio/views.json` (`lib/viewsConfig.js`); a file that can't be read shows Home and can't be changed.
- Add view asks for a name first (`NewFileModal` `kind="view"`; with no name it stays unnamed and shows a light Untitled, `PageTitle`; a rename needs a name), then creates and opens it. Rename / Remove go through `RenameModal` / `DeleteModal` with `kind="view"`. Any view, Home too, can be removed (confirmed); with none left File manager is first.

## Widgets
- Self-contained, one folder each, one line in `widgets/index.js`. A widget gets only `services`: `files`, `folders`, `notes`, `remoteFiles`, `remoteText`, `repoName`, `canEdit`, `config`, `tagColors`, `update`, `openFile`, `openFolder`, `move`, `moveAll`, `rename`, `duplicate`, `remove`, `createFolder`, `newNote`, `addNote`, `noteFile`, `saveNote`, `virtual`, `discards`.
- Optional `title(id, services)` names it in Edit widgets (a board: its folder; notes: Notes), else its label.
- `moved(ch, id, from, to, isDir, services)` follows renames and moves; `removed(ch, id, services)` drops its settings. Optional `fileMoves(id, path, services)` gives the columns an open file can move to; optional `valueScope(id, path, services)` the notes whose property values an open note offers (a board: all its cards, in every column, from any view; else the note's folder).

## Board (`widgets/board/`)
- **Settings:** `.folio/boards/<id>.json`: `folder`, `properties` shown on cards, `hidden` columns, `columns` order, `cards` order per column. Pure logic in `board.js` (tested): `boardColumns`, `movedBoard`, `placeCard`, `moveColumn`, `editNotes`, `withBoardKeys`, `emptyColumn`.
- **Width:** columns share the board's width equally, none narrower than 320px (`min-w-80 flex-1`); below that they keep 320px and the board scrolls sideways. On phones each column is 92% of the board's width, so the next one peeks in from the right, and a swipe snaps to a column.
- **Structure:** a folder whose direct subfolders are columns and whose files, at any depth inside a column, are cards. Files right in the folder show in a No status column first, only while there are any. Technical files and folders (a name starting with `.` or `_`, anywhere in the path) stay off the board, and its property changes leave them and symlinks alone.
- **Card:** the note's title (`noteTitle`: `title` property, else first `# heading`, else file name), its `description` (cut after three lines), the chosen properties' values and, when the note has checklist items, a thin bar with how many are ticked (`2/5`, green once all are; `taskProgress`, outside front matter and code). White (`bg-card`) with an outline and 16px padding; on hover and while dragged a shadow replaces the outline (`border-lift-edge`: a faint one stays on dark). Tapping opens the file in the view (a div with `role="button"`, since its badges are buttons).
- **Card ⋯ (`CardMenu`):** Edit title (T icon; sets the `title` property, or takes it out when emptied: `withTitle`; the file keeps its name; only for a note on this device), Add description / Edit description (its `description`, kept empty when emptied; same condition), Rename file (the file's own name, `RenameModal`, as anywhere else; links and the board's order follow), Duplicate and Copy link (as in the file manager), Move to column (a sub menu of the shown columns, the card's own ticked and disabled; moves the card to the end of that column like a drop; then Edit columns…, which opens the Columns dialog) and Remove (`DeleteModal`). A note opened from a view that has its board gets the same Move to column in its title bar's ⋯ (`ItemMenu` `columns`, from the widget's `fileMoves`).
- **Dragging:** cards and columns drag into any order (`@dnd-kit`, on touch after holding 0.25s). The order is saved in the board's file. A card dropped in another column moves its file into that column's folder (`handleMove`, so links follow; a taken name is refused as a toast). A column moves by its title; No status stays first.
- **Board ⋯:**
  - **Columns** (`CheckListModal`): tick the columns to show; each row has a folder button (opens that column's folder, ← returns to the board) and a trash; a New column field creates one right away.
  - **Properties** (`CheckListModal`): tick the keys its notes have, or add a new name (`keyNameError`); a newly chosen key is added, empty, to every note of the board. A row's pencil renames the key in every note (refused if a note already has the new name); its red trash removes it from all of them, confirmed.
  - **Remove board:** confirmed; deletes its settings file (removing a view removes its boards).
- **Column:** its card count beside the title, swapped for its ⋯ while a mouse is anywhere over the title row (on touch both show). It shows its first 7 cards, then Show N more (shows them all until the board is opened again), a separator and New card.
- **Column ⋯:** Rename, Remove (an empty one plainly; with cards: Remove with cards, or Move to No status, which moves every file in it into the board's folder, numbering taken names, then removes the folder). New card under each column asks for a Title, then a File name that follows the title until typed in (`NewFileModal` `titled`; the title becomes the note's first heading), creates the note there with the board's properties, empty, and stays on the board. Creating a board gives every note in its folder an empty `description`.

## Notes (`widgets/note/`)
- **Settings:** `.folio/notes/<id>.json`: `notes`, a list of `{ file, height }` (`height`: its box's on desktop once resized). An older one-note widget's `{ file, height }` reads as a list of one. Pure logic in `note.js` (tested): `parseNotes`, `noteHeight`, `resizedNote`, `addedNote`, `removedNote`, `reorderedNote`, `movedNotes` (the notes follow renames and moves), `folderNotes`.
- **Widget:** titled **Notes** (also in Edit widgets), with ⋯: Add note… (`NotePicker`: pick a folder, then one of the `.md` files right in it, or **New note…**, `NewFileModal`, made in the same step: `addNote`, App's `noteToAdd`; a note already there isn't added twice), Edit notes… (`EditListModal`: drag into order; a row's trash takes it out, confirmed) and Remove widget. Adding the widget starts with the same picker.
- **Each note** sits in a `Tray` like a board's column, side by side, at least 320px wide; when they don't fit, they wrap onto the next line. Its title row: the note's name, ✏️ Edit (✓ when done) and its own ⋯ (Open full screen; Rename note: renames the file as anywhere else, `RenameModal`; Remove from widget: confirmed, the note stays). Below, the note in a box that scrolls inside, 320px tall on phones; on desktop as tall as its `height` (160–1200px, `NOTE_HEIGHT`), resized by a handle on its bottom edge (`ResizeHandle` `vertical`; ↑/↓ keys; double click resets) and saved there (the default isn't stored): `MarkdownPreview`, or `MarkdownEditor` while editing (Edit, or a double tap at the tapped word, like on the note's page). Edits save on their own through `useNote` and `saveNote`, like on the note's page; ticking a checkbox in the preview edits too. A note that's gone shows as such and can be taken out.
- **Full screen** opens the note in the view, like a board's card (typing is saved first). Removing the widget keeps its notes.
