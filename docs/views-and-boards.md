# Views and boards

## Views
- A view is a dashboard (`ViewPage`): a title bar with ⋯ and + → Add widget (every kind in `widgets/index.js`) over its widgets stacked full width, then an Add widget button under them. Empty: an Add button per kind.
- The view's ⋯: Edit widgets (`EditListModal`: drag rows into order, saved on each drop by `moveWidget`; a row's ✕ removes that widget from the view, confirmed on top of the sheet), Rename, Remove. The navigation's ⋯ keeps only Rename and Remove. A kind this version doesn't know is kept, shown as such, and can be removed. Saved in `.folio/views.json` (`lib/viewsConfig.js`); a file that can't be read shows Home and can't be changed.
- Add view asks for a name first (`NewFileModal` `kind="view"`; with no name it stays unnamed and shows a light Untitled, `PageTitle`; a rename needs a name), then creates and opens it. Rename / Remove go through `RenameModal` / `DeleteModal` with `kind="view"`. Any view, Home too, can be removed (confirmed); with none left File manager is first.

## Widgets
- Self-contained, one folder each, one line in `widgets/index.js` (`board`, `planner`, `note`). A widget gets only `services`: `files`, `folders`, `notes`, `remoteFiles`, `remoteText`, `repoName`, `canEdit`, `config`, `tagColors`, `update`, `openFile`, `openFolder`, `move`, `moveAll`, `rename`, `duplicate`, `remove`, `createFolder`, `newNote`, `addNote`, `noteFile`, `saveNote`, `virtual`, `discards`.
- Optional `title(id, services)` names it in Edit widgets (a board: its folder; notes: Notes), else its label.
- `moved(ch, id, from, to, isDir, services)` follows renames and moves; `removed(ch, id, services)` drops its settings. Optional `fileMoves(id, path, services)` gives the columns an open file can move to; optional `valueScope(id, path, services)` the notes whose property values an open note offers (a board: all its cards, in every column, from any view; else the note's folder).

## Board (`widgets/board/`)
- **Title:** Board, with its folder's path from the repo's root under it, muted (the repo's name for the root). Edit widgets names it by its folder.
- **Settings:** `.folio/boards/<id>.json`: `folder`, `properties` shown on cards, `hidden` columns, `columns` order, `cards` order per column. Pure logic in `board.js` (tested): `boardColumns`, `movedBoard`, `placeCard`, `moveColumn`, `emptyColumn`. What a board and a planner share: `lib/folderNotes.js` (`editNotes`, `withNoteKeys`, `isTechnical`, `fileItem`), `hooks/useFolderNotes.js` (a folder's property keys and values, a card's title, description and removal), and the components `NoteCard`, `CardMenu` (`components/`; without `columns` it has no Move to column) and `CheckListModal` (`locked` names are listed first, ticked and fixed).
- **Width:** columns share the board's width equally, none narrower than 320px (`min-w-80 flex-1`); below that they keep 320px and the board scrolls sideways. On phones each column is 85% of the board's width, at least 280px (`min-w-70`), so the next one peeks in from the right, and a swipe snaps to a column.
- **Structure:** a folder whose direct subfolders are columns and whose files, at any depth inside a column, are cards. Files right in the folder show in a No status column first, only while there are any. Technical files and folders (a name starting with `.` or `_`, anywhere in the path) stay off the board, and its property changes leave them and symlinks alone.
- **Card:** the note's title (`noteTitle`: `title` property, else first `# heading`, else file name), its `description` (cut after three lines; its dates as date badges, like the note's text), the chosen properties' values and, when the note has checklist items, a thin bar with how many are ticked (`2/5`, green once all are; `taskProgress`, outside front matter and code). White (`bg-card`) with an outline and 16px padding; on hover and while dragged a shadow replaces the outline (`border-lift-edge`: a faint one stays on dark). Tapping opens the file in the view (a div with `role="button"`, since its badges are buttons).
- **Card ⋯ (`CardMenu`):** Edit title (T icon; sets the `title` property, or takes it out when emptied: `withTitle`; the file keeps its name; only for a note on this device), Add description / Edit description (its `description`, kept empty when emptied; same condition), Rename file (the file's own name, `RenameModal`, as anywhere else; links and the board's order follow), Duplicate and Copy link (as in the file manager), Move to column (a sub menu of the shown columns, the card's own ticked and disabled; moves the card to the end of that column like a drop; then Edit columns…, which opens the Columns dialog) and Remove (`DeleteModal`). A note opened from a view that has its board gets the same Move to column in its title bar's ⋯ (`ItemMenu` `columns`, from the widget's `fileMoves`).
- **Dragging:** cards and columns drag into any order (`@dnd-kit`, on touch after holding 0.25s). The order is saved in the board's file. A card dropped in another column moves its file into that column's folder (`handleMove`, so links follow; a taken name is refused as a toast). A column moves by its title; No status stays first.
- **Board ⋯:**
  - **Columns** (`CheckListModal`): tick the columns to show; each row has a folder button (opens that column's folder, ← returns to the board) and a trash; a New column field creates one right away.
  - **Properties** (`CheckListModal`): tick the keys its notes have, or add a new name (`keyNameError`); a newly chosen key is added, empty, to every note of the board. A row's pencil renames the key in every note (refused if a note already has the new name); its red trash removes it from all of them, confirmed.
  - **Remove board:** confirmed; deletes its settings file (removing a view removes its boards).
- **Column:** its card count beside the title, swapped for its ⋯ while a mouse is anywhere over the title row (on phones and touch both show; No status has no ⋯). It shows its first 7 cards, then Show N more (shows them all until the board is opened again), a separator and New card.
- **Column ⋯:** Rename, Remove (an empty one plainly; with cards: Remove with cards, or Move to No status, which moves every file in it into the board's folder, numbering taken names, then removes the folder). New card under each column asks for a Title, then a File name that follows the title until typed in (`NewFileModal` `titled`; the title becomes the note's first heading), creates the note there with the board's properties, empty, and stays on the board. Creating a board gives every note in its folder an empty `description`.

## Planner (`widgets/planner/`)
- **Settings:** `.folio/planners/<id>.json`: `folder` and `properties` shown on cards besides the date. Pure logic in `planner.js` (tested): `parsePlanner`, `movedPlanner`, day keys (`dayKey`, `addDays`, `todayKey`), `plan` (what each day lists), `cardDate`, `droppedDate`.
- **Structure:** a folder whose notes, at any depth, are cards, each on the day of its `date` property (any clear format: `valueDate`; written back as "17 Oct 2026", keeping a time). Technical files and folders stay out, as on a board. Choosing the folder (`PlannerSetup`, `FolderSheet`) gives every note in it an empty `date` and `description`.
- **Title:** Planner, with its folder's path under it, muted. Beside ⋯: a Today button that selects today and scrolls to it. ⋯: Properties and Remove planner.
- **Ribbon:** days side by side (56px each) that scroll sideways without end: it starts with today in the middle and grows by 60 days on either side when scrolled near an end. A month's name sits over its days and stays in view while it is scrolled through. A day shows its weekday, number and, when it has cards, how many. Today has a ring, the selected day is filled (today is selected at first; the selection isn't saved).
- **Under it:** the selected day's title and its cards, in a grid, by time then title. Cards without a date always list under today, and cards dated before today list there too, faded (they also stay on their own day). A card is `NoteCard`: its title, description, a date badge (always, empty while the note has none) and the chosen properties; ⋯ as on a board without Move to column.
- **New card** under the list asks for a Title, then a File name that follows it (`NewFileModal` `titled`, as on a board), and creates the note in the planner's folder with the selected day as its date (`newNote` takes `values`) and the planner's properties, empty; the planner stays open.
- **Changing a day:** drag a card onto a day of the ribbon (`@dnd-kit`, on touch after holding 0.25s; its time is kept) or use the date badge's calendar. Both write the note's `date` through `setProperty`.
- **Properties** (`CheckListModal`): as on a board, with the date listed first, ticked and locked (it can't be turned off, renamed or removed here).

## Notes (`widgets/note/`)
- **Settings:** `.folio/notes/<id>.json`: `notes`, a list of `{ file }`, and `height`: the boxes' on desktop once resized, one for all. An older one-note widget's `{ file, height }` reads as a list of one, and a height kept per note as the first one's. Pure logic in `note.js` (tested): `parseNotes`, `notesHeight`, `resizedNotes`, `addedNote`, `removedNote`, `reorderedNote`, `movedNotes` (the notes follow renames and moves), `isNote`.
- **Widget:** titled **Notes** (also in Edit widgets), with ⋯: Add note… (`NotePicker`: search every note in the repo by path, `SearchSheet` with `only`, listing them all by name before anything is typed; or **New note…** on top, which asks for its folder, `FolderSheet`, then its name, `NewFileModal`, made in the same step: `addNote`, App's `noteToAdd`; a note already there isn't added twice), Edit notes… (`EditListModal`: drag into order; a row's ✕ takes it out, confirmed) and Remove widget. Adding the widget starts with the same picker.
- **Each note** sits in a `Tray` like a board's column, side by side, at least 320px wide; when they don't fit, they wrap onto the next line. Its title row: the note's name, ✏️ Edit (✓ when done) and its own ⋯ (Open full screen; Rename note: renames the file as anywhere else, `RenameModal`; Remove from widget: confirmed, the note stays). Below, the note in a box that scrolls inside, 320px tall on phones; on desktop all as tall as the widget's `height` (160–1200px, `NOTE_HEIGHT`), resized together by one handle under them all, edge to edge (`ResizeHandle` `vertical`; ↑/↓ keys; double click resets) and saved there (the default isn't stored): `MarkdownPreview`, or `MarkdownEditor` while editing (Edit, or a double tap at the tapped word, like on the note's page). Edits save on their own through `useNote` and `saveNote`, like on the note's page; ticking a checkbox in the preview edits too. A note that's gone shows as such and can be taken out.
- **Full screen** opens the note in the view, like a board's card (typing is saved first). Removing the widget keeps its notes.
