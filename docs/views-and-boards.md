# Views and boards

## Views
- A view is a dashboard (`ViewPage`): a title bar with ⋯ and + → Add widget (every kind in `widgets/index.js`) over its widgets stacked full width, then an Add widget button under them. Empty: an Add button per kind.
- The view's ⋯: Edit widgets (`EditListModal`: drag rows into order, saved on each drop by `moveWidget`; a row's ✕ removes that widget from the view, confirmed on top of the sheet), Rename, Remove. The navigation's ⋯ keeps only Rename and Remove. A kind this version doesn't know is kept, shown as such, and can be removed. Saved in `.folio/views.json` (`lib/viewsConfig.js`); a file that can't be read shows Home and can't be changed.
- **Views settings** (in the rail and ☰, in place of Add view; `EditListModal`, like a Notes widget's Edit notes): the views in order, dragged into another (`moveView`), each with a red ✕ that removes it (confirmed, `DeleteModal`), and a New view field under them that adds one by name at the end (`addView`; it doesn't open it). A view with no name (an older one) shows a light Untitled (`PageTitle`); a rename needs a name. Rename / Remove from a view's ⋯ go through `RenameModal` / `DeleteModal` with `kind="view"`. Any view, Home too, can be removed (confirmed); with none left File manager is first.

## Widgets
- Self-contained, one folder each, one line in `widgets/index.js` (`board`, `planner`, `note`). A widget gets only `services`: `files`, `folders`, `notes`, `remoteFiles`, `remoteText`, `repoName`, `canEdit`, `config`, `tagColors`, `update`, `openFile`, `openFolder`, `move`, `moveAll`, `rename`, `duplicate`, `remove`, `createFolder`, `newNote`, `addNote`, `noteFile`, `saveNote`, `virtual`, `discards`.
- **Frame:** every widget sits in `WidgetFrame` (`components/WidgetFrame.jsx`): its title row (name, its folder under it, its own controls, ⋯ with its own items, then a separator and Remove), and its body's shared states: a spinner while its settings load, "This … settings can't be read.", and "Its folder … is gone." with Select folder (`FolderSheet`). A widget gives only its own items, controls and body.
- **Properties:** a board's and a planner's Properties sheet is one `PropertiesDialog` (tick, add, rename, remove; removing asks first and takes it out of every note of the folder); each gives only its locked keys (a board's grouping one, a planner's date and repeat) and texts. Showing a new one adds it, empty, to the notes that lack it (`showProperties`).
- Optional `title(id, services)` names it in Edit widgets (a board: its folder; notes: Notes), else its label.
- `moved(ch, id, from, to, isDir, services)` follows renames and moves; `removed(ch, id, services)` drops its settings. Optional `fileMoves(id, path, services)` gives the columns an open file can move to; optional `valueScope(id, path, services)` the notes whose property values an open note offers (a board: all its cards, in every column, from any view; else the note's folder).

## Board (`widgets/board/`)
- **Title:** Board, with its folder's path from the repo's root under it, muted (the repo's name for the root). Edit widgets names it by its folder.
- **Settings:** `.folio/boards/<id>.json`: `folder`, `group` (the property the columns come from; `status` for a new board), `properties` shown on cards, and `groups`: per property it was ever grouped by, its `columns` (values, in order; kept even while no card has one), `hidden` columns and `cards` order per column (paths inside the folder), so switching back restores them. An older file's top-level `columns`, `hidden` and `cards` read as `status`'s. Pure logic in `board.js` (tested): `parseBoard` / `serializeBoard` (in the app the group's own layout sits on the board itself), `groupedBy`, `looseName`, `boardColumns`, `cardStatus`, `movedBoard`, `placeCard`, `moveColumn`, `columnNameError`, `addedColumn`, `renamedColumn`, `removedColumn`; a column's card limit and footer are shared with the planner (`lib/trayCards.js`, `TrayFooter` in `ui/tray.jsx`). What a board and a planner share: `lib/folderNotes.js` (`editNotes`, `withNoteKeys`, `isTechnical`, `fileItem`), `hooks/useFolderNotes.js` (a folder's property keys and values, a card's title, description and removal), and the components `NoteCard`, `CardMenu` (`components/`; without `columns` it has no Move to column) and `CheckListModal` (`locked` names are listed first, ticked and fixed).
- **Width:** columns share the board's width equally, none narrower than 320px (`min-w-80 flex-1`); below that they keep 320px and the board scrolls sideways. On phones each column is 85% of the board's width, at least 280px (`min-w-70`), so the next one peeks in from the right, and a swipe snaps to a column.
- **Structure:** the files in a folder, at any depth, are cards (like a planner's), grouped into a column per value of the board's `group` property (the first value when there are several). When a card's note is saved after editing its markdown without the `group` property, it comes back, empty (`valueScope`'s `required`; when a note is a card of several widgets, the app joins what each requires). Files without a value (and files that aren't notes) show first in a column named after it (No status, No priority…: `looseName`), only while there are any. A card stays where its file is; renaming or moving it (or its subfolder) inside the folder keeps its place. Technical files and folders (a name starting with `.` or `_`, anywhere in the path) stay off the board, and its property changes leave them and symlinks alone.
- **Card:** the note's title (`noteTitle`: `title` property, else first `# heading`, else file name), its `description` (cut after three lines; its dates as date badges, like the note's text), the chosen properties' values and, when the note has checklist items, a thin bar with how many are ticked (`2/5`, green once all are; `taskProgress`, outside front matter and code). White (`bg-card`) with an outline and 16px padding; on hover and while dragged a shadow replaces the outline (`border-lift-edge`: a faint one stays on dark). Tapping opens the file in the view (a div with `role="button"`, since its badges are buttons).
- **Card ⋯ (`CardMenu`):** Add description / Edit description (its `description`, kept empty when emptied; only for a note on this device), Rename (its Title and File name together, `RenameModal` with `TitleNameFields`, as for any note; links and the board's order follow), Duplicate and Copy link (as in the file manager), Move to column (a sub menu of the shown columns, the card's own ticked and disabled; moves the card to the end of that column like a drop, setting its value; then Edit columns…, which opens the Columns dialog) and Remove (`DeleteModal`). A note opened from a view that has its board gets the same Move to column in its title bar's ⋯ (`ItemMenu` `columns`, from the widget's `fileMoves`).
- **Dragging:** cards and columns drag into any order (`@dnd-kit`, on touch after holding 0.25s). The order is saved in the board's file. A card dropped in another column gets that column as its `group` value, in the same step as the order (`placeCardVia`); the file stays where it is. A column moves by its title; No status stays first.
- **Board ⋯:**
  - **Columns** (`CheckListModal`): on top, Group by with the current property (`header`); it opens a dropdown under it, as wide as the row (on phones a side menu would be off screen), of the notes' properties, the current one ticked (a new one is added in Properties first). Picking one switches the columns to it (`groupedBy`: its own layout, or none yet; it's taken off the cards' properties, and the notes that lack it get it, empty). Below, tick the columns to show; each row has a trash; a New column field adds one right away (at the end, saved in `columns`; a taken name is refused).
  - **Properties** (`CheckListModal`): the grouping property first, ticked and locked, with "Grouped by: its values are the columns" under it (`lockedDescription`); cards don't show it, and it can't be added, renamed to or removed here. Renaming or removing another property carries or drops its saved layout in `groups`. Tick the keys its notes have, or add a new name (`keyNameError`); a newly chosen key is added, empty, to every note of the board. A row's pencil renames the key in every note (refused if a note already has the new name); its red trash removes it from all of them, confirmed.
  - **Remove board:** confirmed; deletes its settings file (removing a view removes its boards).
- **Column:** its card count beside the title, swapped for its ⋯ while a mouse is anywhere over the title row (on phones and touch both show; No status has no ⋯). It shows its first 7 cards, then Show N more (shows them all until the board is opened again), a separator and New card.
- **Column ⋯:** Rename (`RenameModal` `kind="column"`: the column and the value of every card in it, in one step; a taken name is refused), Remove (an empty one plainly; with cards: Remove with cards, which deletes their files, or Move to No status, which empties their value). New card under each column asks for a Title and a File name, as every new note does (see Files), creates the note in the board's folder with the column as its value and the board's properties, empty, and stays on the board. Creating a board gives every note in its folder an empty `status` and `description`.

## Planner (`widgets/planner/`)
- **Settings:** `.folio/planners/<id>.json`: `folder`, `properties` shown on cards besides the date and repeat (an older one's `view` is ignored and dropped on the next save). Pure logic in `planner.js` (tested): `parsePlanner`, `movedPlanner`, day keys (`dayKey`, `addDays`, `todayKey`, `daysBetween`), `plan` (what each day lists), `cardDate`, `droppedDate`, `doneNext`, `listed` (the list view's groups), `dayOffsets` / `dayAt` (where days sit on the ribbon); `recurrence.js` (tested): `parseRecurrence`, `formatRecurrence`, `occursOn`, `nextOccurrence`.
- **Structure:** a folder whose notes, at any depth, are cards, each on the day of its `date` property (any clear format: `valueDate`; written back as "17 Oct 2026", keeping a time). Technical files and folders stay out, as on a board. A card's properties come in one order (`ORDER` in `planner.js`): description, date, repeat, then the rest, in its file (new cards are written so, and `withKeysFirst` puts them on top when the planner is set up or one comes back), on the card and on its page (whatever the file's order). Choosing the folder (`PlannerSetup`, `FolderSheet`) gives every note in it an empty `description`, `date` and `repeat` where it lacks one. `date` and `repeat` are fixed (`FIXED`): every card and the note's page show them (empty while the note lacks them); in the markdown editor their lines are greyed out and typing that would change them is refused (see [notes-and-properties](notes-and-properties.md)), so they change only through their badges; when a note is changed in the editor without them, they come back, empty.
- **Repeat** says how often a card happens, in words (`recurrence.js`): `one-time`, `recurring` (repeats, rule not picked yet), `daily` / `weekly` / `monthly` / `yearly`, `every 2 weeks`, weekly ` on Mon, Wed`, and ` until 31 Dec 2026`. A card shows once, on its date, whatever its repeat; a repeating card's date is its next time. Its badge (`RecurrenceField`, given to `PropertyBadges` as `badges`) is accent-colored once it has a value (`bg-primary/10`, `text-primary-ink`; grey while empty), with a calendar-with-a-dot icon for one-time or circling arrows for a repeat, the rule's words, short (`repeatLabel`: Daily / Weekly / Monthly / Yearly, "3 days", "2 weeks", "3 months", "6 years", weekdays alone for weekly ones, "2 weeks · Mon, Wed"; no end date, the popover has it) and no ▾; it opens a popover: One-time / Repeats, Every N Day / Week / Month / Year, the weekdays (weekly; none picked means the date's weekday), and Ends Never / On a day (never before the card's date; a year after it, or after today, at first). A new card is `one-time`.
- **Mark as done** (a card's ⋯, first): a repeating card's date moves on to its next time after its date, keeping its rhythm and time of day; when that's today or before (it fell behind, or it's done on its day), to the first one after today, so one click catches up (`doneNext`); any other card, or one past its `until`, gets `status: done` and moves into today's folder of the archive, `.archive/<day>/` (see [files-and-sync](files-and-sync.md)). A toast says which ("Yoga moved to November 11", "Haircut archived") with Undo.
- **Title:** Planner, with its folder's path under it, muted; on the right an icon-only `Segmented` (calendar / list, `VIEWS`: this device's choice, kept in localStorage per planner, never in `.folio`; calendar at first) and ⋯: New task (on the selected day in the calendar, today in the list), Properties and Remove planner.
- **Ribbon:** in a `Tray` like the cards' below it, days side by side (80px each, white, outlined and rounded like a card and lifting on hover like one, `hover-lift`, with a small gap; 16px from their bottom to the tray's edge) that scroll sideways without end, fading out at both edges (a 32px mask) with no scrollbar: it starts with today in the middle and grows by 60 days on either side when scrolled near an end. Between a month's last day and the next month's first, a short vertical `Separator` (48px, the outline color) takes its own place, in a box `MONTH_GAP` wide, the days' gap on each side (`dayOffsets` places the days for scrolling with the same widths). Over the days, a title row like a column's: the month in the middle of the ribbon (`TrayTitle`; it changes as the ribbon scrolls) and, on the right, a Today button (crosshair icon; accent-colored while another day is selected) that selects today and brings it to the middle, then a calendar button (`DatePopover`). A day picked in the calendar is selected and brought to the middle: scrolled to when the ribbon has it, else the ribbon starts anew around it. A day shows its weekday, number and, when it has cards, how many. Today has a 2px accent outline inside its box, the selected day is filled (today is selected at first; the selection isn't saved).
- **Under it:** a `Tray` like a board's column: the selected day's title ("Today, Saturday", "Tomorrow, Sunday", "Yesterday, Friday", or "November 12", with the year when it isn't this one; no card count, the ribbon has it) with a + on its right (New task on that day), then its cards in a grid, by time then title, the cards of a row one height; the first 7 in one column (phones), 3 whole rows in more (`shownLimit`, `useGridColumns`), then Show N more (`TrayFooter` `grid` without `onNew`, `lib/trayCards.js`; it shows them all until the page is opened again) on a row of its own, one column wide (the full width on phones); a day without cards shows only its title, no message. Cards without a date always list under today with "No date" on their date badge until one is picked, and cards dated before today list there too, their title faded and their date badge red, its fill too, saying "N days ago" in place of the date, in the list view too (`overdue`, `daysAgo`; they also stay on their own day); both have a dashed outline there (the list view has none). A card is `NoteCard`: its title, description, date and repeat badges and the chosen properties; ⋯ as on a board without Move to column, with Mark as done.
- **List view:** instead of the ribbon and the day, every card in grey `Tray` groups of time (`listed`): Today (with the overdue cards first, their title faded and their date red, and the undated last, "No date"; no outline; shown even when it's empty), Tomorrow, This week (to Sunday), This month, This year, Later; each card in exactly one, empty groups hidden. Each group's title has a + (New task on its first day, `first`: today, tomorrow, the day after tomorrow, the day after this week, the 1st of next month, 1 January next year). In a group, a white card holds its tasks as `ListRow`s, by day, time and title, the first 7 and then Show N more (under the card, as for a day; it shows them all until the page is opened again): the title, the date as its description ("N days ago" for a late one) and, for a repeating card, a small grey circling-arrows icon and the repeat (as on its badge) right after it, and the card's ⋯ (`CardMenu` `inRow`: inside the row's padding); a tap opens the note.
- **Folder gone:** instead of the planner, "Its folder … is gone." and Select folder (`EmptyState`), which opens the setup's `FolderSheet`; the picked folder becomes the planner's and its notes are made cards as at setup (`setFolder`, `asCard`). A board does the same, its notes given the grouping property and a description.
- **Nothing today:** when Today has no cards (and nothing overdue), its tray, in both views, shows a white box with ☕ over "All sorted for today" (`EmptyBox`, `SORTED` in `Planner.jsx`). Another empty day stays empty.
- **New task** under the list asks for a Title and a File name (`NewFileModal`, as on a board), and creates the note in the planner's folder with an empty description, the selected day as its date, `repeat: one-time` (`newNote` takes `values`) and the planner's properties, empty; the planner stays open.
- **Changing a day:** drag a card onto a day of the ribbon (`@dnd-kit`, on touch after holding 0.25s; its time is kept) or use the date badge's calendar. Both write the note's `date` through `setProperty` (`reschedule`); when its day changes, a success toast says so ("Haircut moved to November 10", or "… has no date now") with Undo, which writes the old value back. A card let go anywhere but over a day stays as it was. A date that isn't a single day (a range, "soon") counts as no date: the card is dashed with "No date" until a day is picked, which replaces that text.
- **Today:** `useToday` moves it on after midnight and when the app comes back to the screen. Until a day is picked on the ribbon the selected day is today; the ribbon's days are counted from where it started, so they don't shift.
- **Properties** (`CheckListModal`): as on a board, with the date and repeat listed first, ticked and locked (they can't be turned off, renamed to or removed here).

## Notes (`widgets/note/`)
- **Settings:** `.folio/notes/<id>.json`: `notes`, a list of `{ file }`, and `height`: the boxes' on desktop once resized, one for all. An older one-note widget's `{ file, height }` reads as a list of one, and a height kept per note as the first one's. Pure logic in `note.js` (tested): `parseNotes`, `notesHeight`, `resizedNotes`, `addedNote`, `removedNote`, `reorderedNote`, `movedNotes` (the notes follow renames and moves), `isNote`.
- **Widget:** titled **Notes** (also in Edit widgets), with ⋯: Add note… (`NotePicker`: search every note in the repo by path, `SearchSheet` with `only`, listing them all by name before anything is typed; or **New note…** on top, which asks for its folder, `FolderSheet`, then its Title and File name, `NewFileModal`, made in the same step: `addNote`, App's `noteToAdd`; a note already there isn't added twice), Edit notes… (`EditListModal`: drag into order; a row's ✕ takes it out, confirmed) and Remove widget. Adding the widget starts with the same picker.
- **Each note** sits in a `Tray` like a board's column, in a grid of equal columns, as many as fit (up to three) when each can be at least 320px (container queries on the widget), else one; an odd last note keeps its column's width. Its title row: the drag indicator and the note's name, which move the tray among the others like a board's column (`@dnd-kit`, `useDragSensors`: held 0.25s on touch; the tray fades in place while a copy of its title row is dragged; dropped on another note's tray it takes that place, `reorderedNote`; not while the widget can't be saved), and its own ⋯ (Rename note: its Title and File name together, `RenameModal`; Remove from widget: confirmed, the note stays). Below, the note as a card (white, outlined, lifting on hover: `hover-lift`): its preview (`MarkdownPreview` `clip` `compact`: 16px padding, 14px text, smaller headings, less space between blocks), which doesn't scroll: what doesn't fit is cut off under a fade. 200px tall on phones; on desktop all as tall as the widget's `height` (120–1200px, 200 by default, `NOTE_HEIGHT`), resized together by one handle under them all, edge to edge (`ResizeHandle` `vertical`; ↑/↓ keys; double click resets) and saved there (the default isn't stored). Nothing in the preview reacts (`inert`, its checkboxes disabled, no text selection: no scrolling, ticking, links, focus or gestures); a deep fade (half the card, up to 192px) covers its bottom; a tap anywhere on the card opens the note in the view, like a board's card. A note that's gone shows as such and can be taken out.
- Removing the widget keeps its notes.
- **A note that's gone** (removed or moved away outside the widget): its box shows "This note is gone." and Select note (`EmptyState`), which opens `NotePicker` ("Select note") and puts the picked note in its place (`replacedNote`; one already in the widget just takes the gone one out).
