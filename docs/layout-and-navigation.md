# Layout and navigation

## Structure
- **No header.** `AppNav` is the primary navigation.
- **`Surface`** holds the open folder's or file's content: a `bg-card` box next to the rail down to the bottom (on phones under the top bar), scrolling inside, with 16px gutters from 768px (the rail has 16px around it except 8px on its right, and the box 8px on its left, so 16px sit between them). The content (not the title bar) is a centered column of at most 1000px, a view's of at most 1500px (`wide`; files opened from it keep the 1000px limit).
- **`TitleBar`** starts every `Surface`, on every page: Back | Forward as one split button (`ButtonGroup`: two `outline` buttons joined, one border between them; Phosphor `ArrowLeft` / `ArrowRight`), the browser's own history (see Address bar), each off when there's no step of the app's that way; then a file's or folder's icon and name as an outlined button (the buttons' own font, not bold) with ▾ on its right (`TitleMenuButton`; a note's name without `.md`) that opens the folder tree, or on a view the view's tree (see Folder tree); at File manager's root the repo's name, in the same button, opens `RepoMenu`. Pages show their title in bold from `lib/pages.js`, with no icon. Actions on the right: ⋯ (`ItemMenu`), then + (folders), ✏️ Edit or ✓ (notes). At least base height with 16px padding all around, so every title bar is the same height; a bottom border separates it from the content. The title isn't editable: rename from ⋯. There is no bottom bar.

## Rail (from 768px, `NavRail`)
- Items in a group touch; every separator has 16px on both sides.
- Top: logo (`AppLogo`) and name, and a button that collapses the rail to icons only (collapsed: the button shows the logo, turning into its sidebar icon on hover or focus; labels become tooltips; remembered in `storage`). Expanded, its right edge is a drag handle (160–320px). The collapse button is plain `ghost`.
- Then Search (its shortcut on its right as `Kbd` keys, ⌘ K on a Mac, Ctrl K elsewhere; in its tooltip when collapsed) and Sync (`SyncButton`), a separator, the views under a small muted "Views" title with its ⋯ (`ViewsTitle`: New view, which asks for a name and an emoji, `NewFileModal` `kind="view"`, and opens it; Edit views) (collapsed: only the ⋯), a separator, File manager, Assets and Graph (the open page in accent), and at the bottom Recent updates, Broken links (count), Documentation, Settings and Profile (`ProfileSheet`: who's signed in, the reminder email with Edit, a step with ←, and Sign out, red, confirmed).
- A view's emoji (`PageIcon`) replaces its icon, in the rail, ☰ and Edit views, where the icon of each row opens the emoji picker (`EmojiPicker`, a sub popover like a color swatch). Kept in the view's `icon` in `.folio/views.json`; a name starting with an emoji is the icon until one is chosen.
- **Graph** (`GraphPage`): every file and folder of the repo as a dot on a canvas filling the page: notes in the accent, other files grey, folders outlined, the repo's root the largest; a solid line joins each to its folder, a dotted one links two files (`lib/graph.js`; not `.folio`, `.archive` or dot files). The layout settles by itself (d3-force, `useGraphCanvas`), fitted to the page until you move it: drag a dot, drag the background to pan, scroll or pinch to zoom; names show from 90% zoom, and hovering a dot brings out it and its neighbors. A tap on a dot opens a popover beside it (`DotInfo`, anchored with `PopoverAnchor`): its icon and name (a note's title) with a ✕ that closes it, its path after a folder-tree icon (`TreeView`; a folder: how many items are right inside it, `itemsIn`), a note's description and properties as on a widget's card (`PropertyBadges`, read-only), and Open, which alone opens the file or folder in Graph's trail. For the keyboard, a hidden list of buttons, one per dot: Tab brings each dot out as a hover does (`highlight`) and Enter opens its popover (`pointOf`), with the focus in it.
- A view's row shows ⋯ (`ViewMenu` `inRow`: Rename, Emoji, Remove) on hover; File manager and Graph have none.

## Phones (`TopBar`, above the `Surface`)
- 16px from the screen's sides. The menu on the left: ☰ (`List`), then the leaf logo (20px) and Folio (`AppLogo`, `BrandName` `small`) in an outlined button (a button's own padding and gaps, but 12px on the left: ☰ has room of its own inside its box, so the two sides look even); Search and Sync on the right.
- The menu button (`AccountMenu`) opens a `BottomSheet` like every other prompt (Search's too), titled with the logo and Folio: list rows (`ListRow`) for the Views title and the views first, then File manager, Assets and Graph, then Recent updates, Broken links (count), Documentation, Settings and Profile, separated by `Separator`s; the open page highlighted. Choosing one closes it. A view's ⋯ (`ViewMenu`: Rename / Emoji / Remove) is always shown on touch.
- The bar slides away while the content scrolls down (at least 16px in one go) and returns on scrolling up (`useHideOnScroll`), leaving only the title bar fixed: its row folds in 300ms with a gentle ease while what's in it slides up and fades, so the page under it moves softly.
- It does in a note's editor too (each scroll area is followed on its own: the editor's text and its highlighting scroll together). With the keyboard open, the app fills only the part of the screen still seen (`useVisualViewport`, App; Android shrinks the page itself, `interactive-widget=resizes-content` in index.html): iOS would otherwise scroll the whole page up to show the caret, taking the title bar and its ✓ off the screen; this way only the text scrolls, under the title bar.

## Folder tree (`NavTree.jsx`)
- No tree panel. A file's or folder's name in its title bar is a button (`FolderTreeMenu`) that opens a popover with the repo's tree from its root (`RepoTree`), only the folders down to the open item expanded (an open folder too, highlighted), so any folder or file above it is a tap away. Any folder opens and closes there, the path included; that lasts only while the popover is open.
- On a view's page it shows the view's own tree instead (`viewTree` in App): its widgets, then what each shows (a widget kind's `tree`: a Pinned widget's notes and folders (a folder opens in the view), a board's shown columns and their cards, a planner's notes); the nodes holding the open note start expanded. A widget or column row only expands and collapses; a note opens in the view.
- The chevron only expands and collapses (open folders remembered for the session); choosing a folder or file opens it in the page you're on and closes the popover (a symlink opens its source). Each row has the same ⋯ (`ItemMenu`, `inList`) as file manager, shown only on hover with a mouse. The open item is highlighted, and the popover opens scrolled so it shows in the middle (`showCurrent`: again as the popover settles into its height, for its first moments only).
- The repo menu (`RepoMenu`) is File manager's root title: the repos used on this device (the open one checked; another opens the app there, where it was left in that repo; recent files are kept per repo on the device), Switch repository… (disabled while a sync runs), Open on GitHub.

## File manager
Items as a list (`ListRow`), cards (`CardTile`) or columns: the icon-only List | Cards | Columns switch is on top of the title bar's ⋯ menu, cards by default, one choice for every folder, remembered. The root has a menu with only the switch.
- **Columns** (from 768px; phones show cards, keeping the choice): always three columns split by `Separator`s, like a Mac's column view. The open folder is the last one, after its parents (`columnFolders` in `lib/columns.js`; near the root the columns after it stay empty). Each lists its folder as rows, folders first with a chevron; the row of the folder open in the next column is highlighted. A folder opens on a click, so the columns move along; a file opens as anywhere else.

## Trails and pages
- Each main page has its own trail (`trails` in App, rules in `lib/views.js`): the files and folders opened in that page, remembered on this device per repo (across reloads and new sessions). Empty is the page's start (Home's dashboard, Graph, Recent updates' list, File manager's root).
- Files and folders open in the page you're on (from the folder tree, lists, links, symlinks, ↘); Search always opens them in File manager. Back and Forward in the title bar are the browser's: they walk the history of pages, folders and files opened, whatever page they were on. Going up a folder is the folder tree's (under the name). Choosing a view or Graph while on it returns to its start.
- Choosing the page you're on again (rail, ☰) takes it back to its start: a view's, Graph's or Recent updates' own content, File manager's root (`choosePage`).
- An item that's gone (removed, discarded, removed by a Pull or Sync) drops out of every trail. From Settings, Broken links, Documentation or Assets, files open in File manager.
- Pages (`page` in App): a view's id (`home` or an added one) | `files` | `graph` | `settings` | `links`, remembered across reloads; a view that's gone falls back to the first page.

## Address bar (`lib/url.js`)
- File manager: `/folio/<path>` (trailing slash for folders). Home, Graph and Recent updates: `?page=home` / `?page=graph` / `?page=history` (`&root` for the root folder). Settings, Broken links, Documentation and Assets: `?page=settings` / `links` / `docs` / `assets`. Every page, folder and file opened is a history entry (`useAddressBar`): each carries its step (`history.state.step`) and the tab remembers how many there are (sessionStorage), so the title bar's Back and Forward know when there's one to go to and never leave the app (an older entry without a step leaves both on); a rename or delete replaces the entry instead (`replaceNext`).
- The rail's main pages (views, File manager, Graph) are links to where each was left (`hrefOf`: `urlForPage` of its trail's current view): hovering shows the address, and a middle click, ⌘/Ctrl-click or the browser's menu opens or copies it; a plain click opens the page in place.
- Each page, folder or file opened is a history entry; renames, removes and discards replace it. Back / Forward (`popstate`) flush the open note, close any app page and show what the URL names (back along that page's trail if it's on it), or the nearest existing folder if it's gone.
- The app opens at the address it was loaded at if that names a page, folder or file; at the bare address (a new tab, the installed app) it opens where it was left in this repo on this device: the last page and what was open in it (`getPage` / `getTrails`: each tab keeps its own in sessionStorage, so a reload stays where that tab was, and the device keeps the last one per repo in localStorage for a new tab or app start; saved for the repo they belong to, none while signed out; cleared on sign out). Another repo chosen without a reload (signing in again) opens where that repo was left. The deploy copies `index.html` to `404.html` so these URLs load on GitHub Pages.

## Documentation
- A fixed page (`PAGE.DOCS`, `components/Documentation.jsx`), under Broken links in the rail and in ☰, in two tabs (`Segmented`), Markdown first. **Markdown**: a table of the markdown a note can hold (`MARKDOWN_DOCS`: name and syntax, as `lib/markdown.js` renders it), each row with a Copy button copying its syntax as shown; when the renderer learns a new piece, add a row. **Application**: how views and each kind of widget work, in plain words. It lists every kind in `widgets/index.js` with its own label and icon, and its text per kind is `WIDGET_DOCS` in that file; a new widget kind needs a line there (until then it shows "No description yet"). When a widget changes, change its text there too.
