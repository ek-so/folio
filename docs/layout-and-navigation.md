# Layout and navigation

## Structure
- **No header.** `AppNav` is the primary navigation.
- **`Surface`** holds the open folder's or file's content: a `bg-card` box next to the rail down to the bottom (on phones under the top bar), scrolling inside, with 16px gutters from 768px (the rail has 16px around it except 8px on its right, and the box 8px on its left, so 16px sit between them). The content (not the title bar) is a centered column of at most 1000px, a view's of at most 1500px (`wide`; files opened from it keep the 1000px limit).
- **`TitleBar`** starts every `Surface`: ← (Phosphor `ArrowBendLeftUp`, a level up; see Trails and pages), then a file's or folder's icon and name as an outlined button (the buttons' own font, not bold) with ▾ on its right (`TitleMenuButton`; a note's name without `.md`) that opens the folder tree, or on a view the view's tree (see Folder tree); at File manager's root the repo's name, in the same button, opens `RepoMenu`. Pages show their title in bold from `lib/pages.js`, with no icon. Actions on the right: ⋯ (`ItemMenu`), then + (folders), ✏️ Edit or ✓ (notes). At least base height with 16px padding all around, so every title bar is the same height; a bottom border separates it from the content. The title isn't editable: rename from ⋯. There is no bottom bar.

## Rail (from 768px, `NavRail`)
- Items in a group touch; every separator has 16px on both sides.
- Top: logo (`AppLogo`) and name, and a button that collapses the rail to icons only (collapsed: the button shows the logo, turning into its sidebar icon on hover or focus; labels become tooltips; remembered in `storage`). Expanded, its right edge is a drag handle (160–320px). The collapse button is plain `ghost`.
- Then: Search (its shortcut on its right as `Kbd` keys, ⌘ K on a Mac, Ctrl K elsewhere; in its tooltip when collapsed), Sync (`SyncButton`), File manager, Assets and Graph (the open page in accent), a separator, the views and Views settings, and at the bottom Broken links (count), Documentation, Settings and Sign out.
- A view's emoji (`PageIcon`) replaces its icon, in the rail, ☰ and Views settings, where the icon of each row opens the emoji picker (`EmojiPicker`, a sub popover like a color swatch). Kept in the view's `icon` in `.folio/views.json`; a name starting with an emoji is the icon until one is chosen.
- **Graph** (`GraphPage`): every file and folder of the repo as a dot on a canvas filling the page: notes in the accent, other files grey, folders outlined, the repo's root the largest; a solid line joins each to its folder, a dotted one links two files (`lib/graph.js`; not `.folio`, `.archive` or dot files). The layout settles by itself (d3-force, `useGraphCanvas`), fitted to the page until you move it: drag a dot, drag the background to pan, scroll or pinch to zoom; names show from 90% zoom, and hovering a dot brings out it and its neighbors. A tap on a dot opens a popover beside it (`DotInfo`, anchored with `PopoverAnchor`): its icon and name (a note's title) with a ✕ that closes it, its path after a folder-tree icon (`TreeView`; a folder: how many items are right inside it, `itemsIn`), a note's description and properties as on a widget's card (`PropertyBadges`, read-only), and Open, which alone opens the file or folder in Graph's trail. For the keyboard, a hidden list of buttons, one per dot: Tab brings each dot out as a hover does (`highlight`) and Enter opens its popover (`pointOf`), with the focus in it.
- A view's row shows ⋯ (`ViewMenu`: Rename / Remove) on hover; File manager and Graph have none.

## Phones (`TopBar`, above the `Surface`)
- 16px from the screen's sides. ☰, Search and Sync.
- ☰ (`AccountMenu`) opens a left `Sheet` that floats 8px from the screen's edges (as wide as the screen less 16px; 85% from 500px), titled Folio with its logo in a header like a title bar (16px all around), ✕ at the right, level with it; 16px padding inside, header and list alike: list rows (`ListRow`) for File manager, Assets and Graph, the views and Views settings, then, pinned to the bottom of the sheet, Broken links (count), Documentation, Settings and Sign out (red), separated by `Separator`s; the open page highlighted. Choosing one closes it. A view's ⋯ (`ViewMenu`: Rename / Remove) is always shown on touch.
- The bar slides away while the content scrolls down (at least 16px in one go) and returns on scrolling up (`useHideOnScroll`), leaving only the title bar fixed: its row folds in 300ms with a gentle ease while what's in it slides up and fades, so the page under it moves softly.

## Folder tree (`NavTree.jsx`)
- No tree panel. A file's or folder's name in its title bar is a button (`FolderTreeMenu`) that opens a popover with the tree around the open item: an open file's folder, or for an open folder its parent, with the folder itself shown open and highlighted among its neighbours (its chevron stays open); at the root, the root's items.
- On a view's page it shows the view's own tree instead (`viewTree` in App): its widgets, then what each shows (a widget kind's `tree`: a Pinned widget's notes and folders (a folder opens in the view), a board's shown columns and their cards, a planner's notes); the nodes holding the open note start expanded. A widget or column row only expands and collapses; a note opens in the view.
- The chevron only expands and collapses (open folders remembered for the session); choosing a folder or file opens it in the page you're on and closes the popover (a symlink opens its source). Each row has the same ⋯ (`ItemMenu`, `inList`) as file manager, shown only on hover with a mouse. The open item is highlighted, and the popover opens scrolled so it shows in the middle (`showCurrent`).
- The repo menu (`RepoMenu`) is File manager's root title: the repos used on this device (the open one checked; another opens the app there, keeping the page and starting its trails and recent files afresh), Switch repository… (disabled while a sync runs), Open on GitHub.

## File manager
Items as a list (`ListRow`), cards (`CardTile`) or columns: the icon-only List | Cards | Columns switch is on top of the title bar's ⋯ menu, cards by default, one choice for every folder, remembered. The root has a menu with only the switch.
- **Columns** (from 768px; phones show cards, keeping the choice): always three columns split by `Separator`s, like a Mac's column view. The open folder is the last one, after its parents (`columnFolders` in `lib/columns.js`; near the root the columns after it stay empty). Each lists its folder as rows, folders first with a chevron; the row of the folder open in the next column is highlighted. A folder opens on a click, so the columns move along; a file opens as anywhere else.

## Trails and pages
- Each main page has its own trail (`trails` in App, rules in `lib/views.js`): the files and folders opened in that page, remembered across reloads. Empty is the page's start (Home's dashboard, Graph, File manager's root).
- Files and folders open in the page you're on (from the folder tree, lists, links, symlinks, ↘); Search always opens them in File manager. ← isn't the browser's Back (`upView` in `lib/views.js`): in File manager it goes a level up in the folders (a file to its folder, a folder to its parent); on a view or Graph it goes back along the page's trail, the way you drilled down, and from the first item to the page's start (the view itself). File manager's root, a page's start, Settings and Broken links have no ←; the browser's Back still walks the history. Choosing a view or Graph while on it returns to its start.
- Choosing the page you're on again (rail, ☰) takes it back to its start: a view's or Graph's own content, File manager's root (`choosePage`).
- An item that's gone (removed, discarded, removed by a Pull or Sync) drops out of every trail. From Settings, Broken links or Documentation, files open in File manager.
- Pages (`page` in App): a view's id (`home` or an added one) | `files` | `graph` | `settings` | `links`, remembered across reloads; a view that's gone falls back to the first page.

## Address bar (`lib/url.js`)
- File manager: `/folio/<path>` (trailing slash for folders). Home and Graph: `?page=home` / `?page=graph` (`&root` for the root folder). Settings, Broken links and Documentation leave the address as it is.
- The rail's main pages (views, File manager, Graph) are links to where each was left (`hrefOf`: `urlForPage` of its trail's current view): hovering shows the address, and a middle click, ⌘/Ctrl-click or the browser's menu opens or copies it; a plain click opens the page in place.
- Each page, folder or file opened is a history entry; renames, removes and discards replace it. Back / Forward (`popstate`) flush the open note, close any app page and show what the URL names (back along that page's trail if it's on it), or the nearest existing folder if it's gone.
- The app opens at the address it was loaded at if that names a page, folder or file. The deploy copies `index.html` to `404.html` so these URLs load on GitHub Pages.

## Documentation
- A fixed page (`PAGE.DOCS`, `components/Documentation.jsx`), under Broken links in the rail and in ☰: how views and each kind of widget work, in plain words. It lists every kind in `widgets/index.js` with its own label and icon, and its text per kind is `WIDGET_DOCS` in that file; a new widget kind needs a line there (until then it shows "No description yet"). When a widget changes, change its text there too.
