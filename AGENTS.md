# Folio — Agent Instructions

React + Vite PWA. Reads/writes markdown files from any GitHub repo via the GitHub REST API.

## How to work with me
- **Ask before building.** Clarify scope before writing code. You may suggest, but never implement more than what was explicitly confirmed.
- **Be concise.** Short sentences. No filler. No summaries of what you just did.
- **Always work on `main` and push every commit to it.** No branches, no pull requests. If a push is refused, say so; don't leave commits unpushed.

## Principles
1. **One way to do each thing.** Before adding a component, pattern or helper, look for an existing one and reuse or extend it. Two solutions to one problem drift apart and double the bugs.
2. **One source of truth; derive the rest.** Store the minimum state and compute everything else from it. Never keep a copy that can get out of sync.
3. **Logic in pure functions, effects in hooks, rendering in components.** Rules about data live in plain, testable functions. Hooks own network, storage and timers. Components only display and forward user actions.
4. **One path for every write.** All changes go through the same pipeline. Side doors skip the rules everything else follows.
5. **Never lose the user's work.** Save before acting. After an operation, clear only what you know succeeded. Confirm before destroying. Don't allow editing what can't be saved.
6. **Assume the network can disappear at any moment.** Every remote call has an offline answer. Tell "offline", "rejected" and "broken" apart and handle each.
7. **Fail visibly, recover calmly.** Show a clear state for loading, empty, error and offline. Never swallow an error in a way that leaves the screen lying.
8. **Design system first.** Use the shared components and theme tokens. A one-off style or color is a future inconsistency.
9. **Small changes, verified before shipping.** Build, run tests and lint (`npm run lint`), and check the change once in the real app. Test logic, not pixels; keep tests few and meaningful.
10. **Replace means remove.** When something new replaces something old, delete the old code in the same change.

## Keeping this file true
This file is only useful while it matches the code. Before relying on a rule or description here, check it against the code; whenever a change makes any line here wrong or incomplete, fix that line in the same commit. If the code and this file disagree and it's unclear which is intended, ask.

## Code reviews
Suggest a full code review from time to time: after a larger feature, or after roughly 10 changes since the last review. Review against the principles above, list findings by priority, and fix only what's confirmed.

## Design system — shadcn/ui + Tailwind v4

**Spacing tokens** (`--space` 16px, `--space-sm` 8px, `--space-xs` 4px in `src/index.css`; classes `p-space`, `gap-space-sm`, `px-space-xs`, `inset-x-space`…, or `var(--space)`): 16px is the base, for the gutters around the rail, tree and content box, the gaps between them, and the floating panel's distance from the screen's edges. 8px is the small step: inside a piece (title bar, list and tree padding, gaps between buttons) and the phone tree drawer's distance from the edges. 4px is the extra small step: a title's own side padding in title bars (the tree panel's title is a regular button, `RepoMenu`).

**Stack:** shadcn/ui (new-york style) · Tailwind CSS v4 · Radix UI primitives · Phosphor icons (`@phosphor-icons/react`, regular weight — except ⋯ `DotsThree`, bold for visibility)

### Rules
- Use shadcn components from `src/components/ui/` for all interactive elements. Add new ones with `npx shadcn@latest add <component>`.
- Use Tailwind utility classes for layout and spacing. Never write custom CSS for things Tailwind covers.
- Use `cn()` from `@/lib/utils` to merge classes conditionally.
- **Three control sizes, set as tokens** in `src/index.css`: base `--spacing-control` (40px), medium `--spacing-control-md` (32px) and small `--spacing-control-sm` (24px). Use `h-control`, `size-control`, `min-h-control` (and `-md`, `-sm`); never hardcode a pixel height. Every tappable or input element is base: `Button` (default), `size="icon"`, `Input`, menu items, list rows, sheet and dialog close, the title bar's tree button. Small (`Button size="sm"`) is for secondary controls beside the title, such as the symlink button (`SymlinkedBy`). Medium (`Button size="md"`, or `size-control-md` for a square) is the tree's expand chevrons and the ⋯ inside file-list rows (inside the row's base-height highlight, which hovering it highlights) (24px lines with an invisible 40px tap area). Build controls from `Button`/`Input` instead of raw elements; don't override heights. All controls share one radius, `rounded-sm` (8px). Exceptions: segmented toggles (`ui/segmented.jsx`: a base-height `rounded-sm` track, `p-1`, with `rounded` segments filling it); two-line result rows (search, backlinks), which grow from the base minimum.
- **Icons are 16px** (`size-4`). `Button` and menu items size icons by default — don't pass size classes.
- **File icons** come from `FileIcon` (20px Phosphor): folder yellowish (`text-folder`), note and other files blue (`text-primary`), PDF red (`text-destructive`), image green (`text-file-image`). A symlink shows the icon of what it points to with a small ↗ in the corner (`link`).
- **No header; `AppNav` is the primary navigation.** From 768px a labeled left rail (`NavRail`): on top the app's logo (`AppLogo`, also on the sign-in screen; same artwork as the favicon and home-screen icons in `public/`) and name (Folio, bold) and a button that collapses the rail to icons only (collapsed, that button shows the logo, turning into its sidebar icon on hover or focus; labels become tooltips, `SyncButton` `compact`: one icon button with a dot for changes that opens the same menu with Sync all on top; remembered in `storage`; expanded, its right edge is a drag handle, 160–320px), and to its right, while the file tree is hidden, a tree button (`TreeView`) that shows it again (collapsed rail: under the logo); then Sync (`SyncButton`) and Search, then Home, File manager, Graph (the open one in accent: light accent fill and accent text), and at the bottom Broken links (count), Settings and Sign out as plain buttons. On phones a floating panel at the bottom (`FloatingNav`; hidden while the keyboard is up; it floats over the content, whose scroll areas end with `max-md:pb-nav` so the last lines clear it): ☰ (`AccountMenu` popover: the three pages, then Broken links (count), Settings, Sign out; the open one checked), Search and Sync. Every page's `Surface` starts with a `TitleBar`: files and folders show their name, Home, Graph, Settings and Broken links (`page` prop; titles in `lib/pages.js`) show their title; no icons. A file or folder shows ← before its name when its page has a step to go back to; a page's start (Home's dashboard, Graph, File manager's root) and Settings and Broken links have none: they're opened from the menu and left through the navigation; a file opened from Broken links opens in File manager. Each main page has its own navigation (`trails` in App, rules in `lib/views.js`: the files and folders opened in that page, the last one shown; empty is the page's start: Home's dashboard, the graph, File manager's root; remembered across reloads): files and folders open in the page you're on, from the tree, lists, links, symlinks and ↘, and ← goes back one step in that page only (when that's also the browser's previous entry it's the browser's Back, `prev` in `history.state`). Choosing Home or Graph in the navigation while on it takes it back to its start; an item that's gone (deleted, discarded, removed by a Pull or Sync) drops out of every trail (one effect in App watching the files), so each page shows what it showed before. From Settings or Broken links they open in File manager.
- **`Surface`** holds the open folder's or file's content: a `bg-card` box (white in light mode, slightly lighter grey than the page in dark) next to the rail down to the bottom of the screen (on phones above the floating panel), scrolling inside. On phones it's no box at all: the page's own `bg-background`, edge to edge, no outline or rounded corners; from 640px it's a fully rounded box with 16px gutters. The rail, the tree (resizable, 300px by default) and the box fill the window; the box grows with it, and its content (not the title bar) is a centered column of at most 1000px, except Home's (`wide`: a dashboard, the full width; files and folders opened from it keep the limit). On top it has `TitleBar`: with `tree`, on phones the file-tree button (`NavDrawerButton`), then ← (when there's a step back) and the item's name in bold, in its own block with 4px side padding, 8px after the button (a note's without `.md`; the repo's name at the root). Then the item's actions on the right: ⋯ (`ItemMenu`), then + (folders), ✏️ Edit (a note in preview) or ✓ (while editing); its row is at least base height (40px) with 8px padding around, so every title bar is the same height, the tree panel's title too; a bottom border separates it from the content. The title isn't editable: rename from ⋯. There is no bottom bar. A note's `# heading` stays in its markdown and shows in the preview and the editor like any other line.
- Tooltips are the browser's own (`title`): no custom tooltip code. They show on hover only (not on phones), so nothing essential may depend on them.
- Never hardcode colors — use Tailwind semantic tokens (`bg-background`, `text-foreground`, `text-muted-foreground`, `bg-primary`, etc.).

## Architecture

App flow: **Auth → RepoSetup → FileBrowser / Editor / FileViewer** (`App.jsx` is layout and UI actions). Token and repo are always user-supplied at runtime; nothing is hardcoded.

### Code map
- `lib/github.js` — all GitHub API calls (`init(token)`, `setRepo(owner, repo)`); blob reads go through the offline cache; failures are tagged with the step they happened at.
- `lib/changes.js` — pure model of local changes (edits, uploads, renames, deletes, new files) layered over the remote tree. Tested in `changes.test.js` (`npm test`).
- `lib/markdown.js` — preview rendering (blocks tagged with their source range; a `<details>` accordion is one block; smart tables: a real ISO date `2025-03-18` in a table cell, outside code and links, shows as a date chip, `.date-chip` in `App.css`), tap-to-source (`tapOffset`), task checkboxes (`taskOffsets`), editor highlighting, image paths.
- `lib/links.js` — internal links (regular markdown only, no wiki links; code ignored): the backlink / broken-link index, rewriting links when files move (same style: relative, `.md` or not, encoding, anchors; link text equal to the old name follows), Fix suggestions, and `resolveSymlink`. Tested in `links.test.js`.
- `lib/tree.js` — which folders the file tree opens for a path (`tree.test.js`).
- `lib/views.js` — each main page's trail of views (`openView`, `currentView`, `trailTo` for Back / Forward) and how trails follow moves and deletes (`views.test.js`).
- `lib/pages.js` — the page ids (`PAGE`) and the title and icon of every page (`pageInfo`), and the main ones (`MAIN_PAGES`), used by the navigation, title bars and App.
- `lib/files.js` (file-type and name helpers), `lib/cache.js` (IndexedDB copies of the last tree and of blobs by sha), `lib/storage.js` (localStorage/sessionStorage: token, repo, repos used on this device, user, theme, local changes, each main page's view, page, recent files), `lib/syncErrors.js`, `lib/updates.js`, `lib/viewport.js`.
- `hooks/` — `useAuth`, `useRepo` (remote tree, local changes, sync), `useNote`, `useLinkIndex`, `useSymlinks`, `useBlob`, `useRepoImages`, `useTheme`.

### Behaviour
- **Notes:** `Editor` switches between `MarkdownPreview` (read-only apart from task checkboxes and accordions; open accordions stay open across re-renders) and `MarkdownEditor` (highlighted textarea). ✏️ opens the editor at the first block on screen (`visibleOffset`); a double tap or double click on text opens it at that word (counted from two clicks, since iPhones send no dblclick). Closing the keyboard (iOS Done, tapping elsewhere, Escape) or ✓ returns to preview.
- **Images and PDFs** open read-only in `FileViewer` (`useBlob`); PDFs use pdf.js (`PdfView`, loaded on first use) and draw only pages near the screen, for iOS memory. `Editor` and `FileViewer` share `FilePage`.
- **Symlinks** (git mode `120000`) never open themselves. A link row is dimmed with "(symlink)" after its name (desktop tooltip: "Symlinked from <path>"); opening a link — from the list, search or a note's link (`setSelectedFile` in App) — opens its source. Links outside the repo, to nothing, or not on the device yet show the reason and can't be opened. Folder links sort with the folders. A file or folder that links point to shows them in its title bar right after the title (`SymlinkedBy`, the `badge` of `TitleBar`): a ↘ button (the reverse of the symlink's own ↗) styled like ⋯ that shows the link's name and opens it, or (↘ and a count) lists their paths; choosing one goes to the folder holding that link.
- **Links:** `useLinkIndex` indexes every note (local edit, else the offline copy) on the device; nothing is stored in the repo. Notes show `Backlinks` under the preview. Sync and Push first check the whole repo for broken links: if any, `SyncCheckModal` lists them (`BrokenLinkList`, shared with the Broken links page) with Fix, Open Broken links and Sync anyway. Rename and Move rewrite every affected link in the same local changes; the sheets say how many notes are affected (`LinksContext`).
- **Uploads:** drop files on the file list (into the open folder or onto a folder row) or + → Upload files…. `handleUpload` in App stores each file's bytes in the offline cache under its git sha (`blobShaOf`) and records an upload in the local changes; Sync uploads the blobs (`uploadBlob`) in the one commit. A taken name asks Replace / Keep both (`freePath`) / Skip (`UploadClashModal`); invalid or over-25 MB files are listed in `UploadErrorsModal`. Unused bytes are dropped from the cache (`dropUnusedUploads`).
- **File tree** (`NavTree.jsx`, state in App, `NavContext`): every main page's `Surface` (`tree`) has the repo's folders and files, from the root's own level (no root row), in their own `bg-card` box to its left from 768px (300px by default; the 16px gap to the content is a drag handle, also ←/→ keys, double click resets; 200–480px, remembered in `storage`; the same `ResizeHandle` and `useResizableWidth`, limits in `lib/resize.js`, also resize the rail; each is at most 35% / 25% of the window so the content keeps room), titled with the repo's name (same height and border as the `TitleBar`; one `TreePanel` for both) as a menu (`RepoMenu`): the repos used on this device (`repos` from `useAuth`; the open one checked, another one opens the app there: `switchRepo` in `useAuth` keeps the page and starts the repo's trails, open folders and recent files afresh; each repo's local changes stay stored under it), Switch repository… (disabled while a sync runs, so it's never cut off; a `BottomSheet` with `RepoForm`, the owner/repo field the setup screen uses too, checked with GitHub by `checkRepo(owner, repo)`) and Open on GitHub, with Collapse all at the right of the title (disabled while no top-level folder is open; in the drawer before ✕, split by a thin vertical line), then on desktop « (`CaretDoubleLeft`) that hides the panel (`treeCollapsed` in App, remembered in `storage`; the rail's tree button brings it back); below 768px the title bar's tree button (`TreeView`, the same icon) opens the same panel in a left `Sheet` (✕ at the right of the title) that floats like a popover (`bg-card`, rounded, 8px from the screen's edges; the full width minus those gutters below 500px, 85% of the screen above). The chevron (a medium square with its own hover fill, like ⋯ in list rows) only expands and collapses (`expanded`, remembered per session); the name opens the folder in the page you're on and expands it; choosing a file opens it in the page you're on (a symlink opens its source). Each row has the same ⋯ (`ItemMenu`, `inList`) as File manager's rows; with a mouse it shows only while the row is hovered (`hoverReveal`). The open file or folder is highlighted and always revealed (`foldersToOpen`). Drag and drop (desktop panel only, not the phone drawer): a row dropped on a folder moves there (on a file: into its folder; on the empty area: the root), a collapsed folder held under a drag opens after 0.6s, and files from the device upload there; the rule for where an item may go is `canMoveTo` (also used by `MoveModal`). Drag moves in the tree and the file list go through `handleDropMove` in App, which shows a refusal as a toast.
- **Item actions:** Rename / Move / Delete for any file or folder (the only way to rename) go through `ItemMenu` (⋯), on list rows, file tree rows and in the title bar. `SearchSheet` finds visible files by path; with no query it lists recently opened ones.
- **Offline and sync:** a service worker (vite-plugin-pwa) caches the app and all notes are prefetched to IndexedDB. Every change is local until Sync, which makes one commit; GitHub's state after it is computed locally (`filesAfter`, `blobSha`), so a dropped connection can't leave pushed changes looking unsynced. The app never downloads GitHub's changes by itself: on start, return, coming online and pull-to-refresh it only checks for new commits (`checkRemote`) and shows the dot; files change only on Sync or Pull (a repo never opened on this device downloads on start). Success shows a toast (`ui/sonner`: bottom center, filled emerald, a 20px icon and the text, 16px padding; on phones full width above the floating panel; Synced / Pulled; `useRepo` reports it through `onDone`, App shows it); `SyncButton` flashes only Failed and Offline. `SyncButton` is a split button (`ghost-outline`): Sync, plus ▾ with Push (blue count badge) / Pull (blue badge from `changedFileCount`; "New" when GitHub can't compare) / Discard (confirms via `DiscardModal`); the badge on Sync shows only directions (↑ ↓; 12px arrows, as tall as the menu badges: a 20px circle with one, a pill with both). A failed Sync / Push / Pull (not offline) opens `SyncErrorModal` (`describeSyncError`: plain explanation, what to do, GitHub's raw answer, the failed step, Try again). `lib/updates.js` reloads for new versions on start and on return, never while typing.
- **Navigation:** the address bar mirrors the main page you're on and its view (built and read by `lib/url.js`, tested in `url.test.js`): File manager's is `/folio/<path>` (trailing slash for folders); Home's and Graph's add `?page=home` / `?page=graph` (no path: their own content; `&root` for the root folder). Each page, folder or file opened is a history entry. Back / Forward (`popstate` in App) flush the open note, close any app page and show the page and view the URL names (back along that page's trail if it's on it), or its nearest existing folder if it's gone; renames, deletes and discards replace the entry instead of adding one. Settings and Broken links aren't in the address and leave it as it is. The app opens at the address it was loaded at if that names a page, folder or file. The deploy copies `index.html` to `404.html` so those URLs load on GitHub Pages. The navigation (`AppNav`) opens Home, File manager, Graph, Broken links, Settings; all of them are `page` in App (`home` | `files` | `graph` | `settings` | `links`, remembered across reloads: a reload always returns to the page you were on; otherwise the app starts on the page the address names, else the first one in the navigation (Home)).
- **Overlays:** prompts use `BottomSheet` (a sheet on mobile, a centered shadcn Dialog from 768px). Dropdown menus are non-modal (`ui/dropdown-menu` default): a modal menu that opens a dialog can leave the page locked and freeze every button; `BottomSheet` also clears a stale lock on close, and on iOS `lib/viewport.js` scrolls the page back after the keyboard closes. Loading uses `Spinner`. `PullToRefresh` wraps every screen; `data-no-pull` areas opt out.
